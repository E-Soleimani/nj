Working
with Streams

عمیق‌تر در دنیای Streams — چهار نوع stream، pipeline امن، و backpressure که یکی از مهم‌ترین مفاهیم برای پردازش داده حجیم در Node.js است.

Stream چیست؟ یادآوری از فصل ۱۵

در فصل Non-Blocking & Concurrency با مفهوم Stream آشنا شدید — پردازش داده تکه‌تکه به جای لود کامل در حافظه. در این فصل عمیق‌تر می‌رویم: چهار نوع Stream، نحوه کار با هرکدام، و backpressure که یکی از مفاهیم کلیدی و کمتر دانسته‌شده است.

چهار نوع Stream در Node.js

Readable

داده از آن می‌خوانید — مثل fs.createReadStream، HTTP request body

Writable

داده به آن می‌نویسید — مثل fs.createWriteStream، HTTP response

Duplex

هم Readable هم Writable — مثل TCP socket

Transform

یک Duplex خاص که داده ورودی را تبدیل می‌کند — مثل gzip، encryption

کار با Readable Stream — دو روش

readable-modes.js
const fs = require('fs'); // روش ۱: event-based (Flowing mode) const stream1 = fs.createReadStream('big-file.csv', { encoding: 'utf8' }); stream1.on('data', (chunk) => { console.log(`دریافت ${chunk.length} بایت`); }); stream1.on('end', () => console.log('تمام شد')); stream1.on('error', (err) => console.error(err)); // روش ۲: async iteration — مدرن‌تر و خواناتر (Node.js 10+) async function readFileWithAsyncIteration() { const stream2 = fs.createReadStream('big-file.csv', { encoding: 'utf8' }); for await (const chunk of stream2) { console.log(`پردازش chunk: ${chunk.length} بایت`); // می‌توانید await هم بزنید داخل حلقه — برخلاف event-based await processChunk(chunk); } console.log('تمام شد'); }

Pipeline — ترکیب چند Stream با هم

pipeline() روش امن و توصیه‌شده برای زنجیر کردن streamهاست — خودکار خطاها و cleanup را مدیریت می‌کند (برخلاف .pipe() ساده):

pipeline-example.js
const { pipeline } = require('stream/promises'); // نسخه Promise-based const fs = require('fs'); const zlib = require('zlib'); // خواندن یک فایل، فشرده‌سازی، نوشتن — همه با stream، بدون لود کامل در RAM async function compressFile(inputPath, outputPath) { try { await pipeline( fs.createReadStream(inputPath), zlib.createGzip(), // Transform stream — فشرده می‌کند fs.createWriteStream(outputPath) ); console.log('فشرده‌سازی با موفقیت تمام شد'); } catch (err) { console.error('خطا در pipeline:', err.message); // pipeline خودکار همه streamها را cleanup می‌کند } } compressFile('data.txt', 'data.txt.gz'); // مثال واقعی‌تر — پردازش CSV حجیم و آپلود به S3 با stream // بدون اینکه کل فایل را در RAM نگه دارد async function processLargeCSV(filePath) { const csvParser = require('csv-parser')(); await pipeline( fs.createReadStream(filePath), csvParser, async function* (source) { for await (const row of source) { yield await transformRow(row); } } ); }
⚠️

چرا نه .pipe()؟ اگر یک stream در میانه خطا بدهد، .pipe() بقیه streamها را به درستی نمی‌بندد — memory leak ممکن است. همیشه از pipeline() استفاده کنید.

Backpressure — مفهوم کلیدی

Backpressure یعنی وقتی Writable stream نمی‌تواند به سرعت Readable داده تولید می‌کند، پردازش کند. Node.js این را خودکار مدیریت می‌کند، اما باید بدانید چطور:

backpressure.js
const fs = require('fs'); const readStream = fs.createReadStream('huge-file.txt'); const writeStream = fs.createWriteStream('output.txt'); readStream.on('data', (chunk) => { // write() مقدار boolean برمی‌گرداند // false یعنی: بافر داخلی writeStream پر شده — صبر کن! const canContinue = writeStream.write(chunk); if (!canContinue) { readStream.pause(); // خواندن را موقتاً متوقف کن } }); // وقتی writeStream آماده داده بیشتر شد، این رویداد emit می‌شود writeStream.on('drain', () => { readStream.resume(); // دوباره شروع به خواندن کن }); // خوشبختانه pipe() و pipeline() این کار را خودکار انجام می‌دهند! // به همین دلیل همیشه ترجیح داده می‌شوند به مدیریت دستی backpressure

نکات کلیدی برای مصاحبه

  • چهار نوع stream: Readable، Writable، Duplex، Transform.
  • for await...of روش مدرن خواندن stream است — اجازه await داخل حلقه را می‌دهد.
  • pipeline() از .pipe() امن‌تر است — خودکار خطا و cleanup را مدیریت می‌کند.
  • Backpressure: وقتی writer از reader کندتر است، باید سرعت خواندن را کاهش دهیم.
  • وقتی write() false برمی‌گرداند، یعنی بافر پر شده — منتظر رویداد 'drain' بمانید.
  • Streamها برای فایل‌های بزرگ، video/audio streaming و پردازش real-time ضروری‌اند.
  • سوال رایج: «چرا از stream استفاده کنیم به جای خواندن کل فایل با readFile؟» — اگر فایل خیلی بزرگ باشد (مثلاً چند گیگابایت)، readFile کل آن را در RAM می‌ریزد و ممکن است حافظه سرور را پر کند؛ stream فقط یک تکه کوچک را در حافظه نگه می‌دارد.
  • یک تله رایج: استفاده از .pipe() بدون مدیریت خطا — اگر یک stream در وسط راه خطا بدهد، ممکن است بقیه streamها به درستی بسته نشوند (memory leak)؛ pipeline() این را خودکار حل می‌کند.
  • Duplex stream هم Readable هم Writable است (مثل TCP socket)؛ Transform یک Duplex خاص است که داده ورودی را تغییر می‌دهد قبل از خروجی (مثل gzip).
  • Backpressure خودکار توسط pipe/pipeline مدیریت می‌شود؛ فقط وقتی دستی با on('data') کار می‌کنید باید خودتان pause/resume را مدیریت کنید.
