Chat Server

HTTP معمولی request-response است — client می‌پرسد، سرور جواب می‌دهد. اما برای chat، server باید خودش بدون درخواست پیام بفرستد. WebSocket این امکان را می‌دهد. یاد می‌گیریم با Socket.io یک chat server واقعی بسازیم.

WebSocket Socket.io Rooms Real-time Broadcast

HTTP vs WebSocket — چه فرقی دارند؟

HTTP مثل پست معمولی است: شما نامه می‌فرستید، جواب می‌گیرید، تمام. هر بار یک اتصال جدید باز می‌شود و بسته می‌شود. اما برای chat، سرور باید هر وقت پیام جدیدی آمد، خودش به همه بفرستد — بدون اینکه کلاینت بپرسد.

WebSocket یک اتصال دو‌طرفه دائمی ایجاد می‌کند. مثل تلفن: یک بار وصل می‌شوید و می‌توانید هر وقت صحبت کنید.

هر client یک اتصال دائمی دارد — پیام‌ها لحظه‌ای رد و بدل می‌شوند

Socket.io چیست؟

Socket.io یک کتابخانه است که WebSocket را ساده‌تر می‌کند. امکاناتی مثل Rooms (اتاق‌های چت)، auto-reconnect، و fallback (اگر WebSocket نشد، polling) را به صورت built-in دارد.

terminal — نصب
npm install socket.io npm install socket.io-client # برای client (اگر Node.js client بود)

سرور Chat پایه

server.js — Chat Server کامل
const http = require('http'); const { Server } = require('socket.io'); const httpServer = http.createServer(); const io = new Server(httpServer, { cors: { origin: '*' } // در production origin محدود کنید }); // نگه داشتن لیست کاربران آنلاین const onlineUsers = new Map(); // socketId → { username, room } // io.on('connection') — وقتی یک client وصل می‌شود io.on('connection', (socket) => { console.log(`کاربر جدید وصل شد: ${socket.id}`); // رویداد join — کاربر به یک room می‌پیوندد socket.on('join', ({ username, room }) => { // socket.join — این socket را به room اضافه می‌کند socket.join(room); // ذخیره اطلاعات کاربر onlineUsers.set(socket.id, { username, room }); // به همه در room بگو کاربر جدید آمد (به جز خودش) socket.to(room).emit('user-joined', { username, message: `${username} به اتاق پیوست`, time: new Date().toISOString() }); // لیست کاربران آنلاین این room const roomUsers = [...onlineUsers.values()] .filter(u => u.room === room) .map(u => u.username); // فقط به این socket بگو (نه بقیه) socket.emit('room-users', roomUsers); }); // رویداد message — وقتی پیام می‌فرستد socket.on('message', ({ text, room }) => { const user = onlineUsers.get(socket.id); if (!user) return; const messageData = { id: Date.now(), username: user.username, text: text.trim(), time: new Date().toISOString() }; // io.to(room) — به همه در room بفرست (شامل خودش هم) io.to(room).emit('message', messageData); }); // رویداد typing — تایپ کردن socket.on('typing', ({ room, isTyping }) => { const user = onlineUsers.get(socket.id); if (!user) return; // به بقیه room بگو (نه خودش) socket.to(room).emit('user-typing', { username: user.username, isTyping }); }); // disconnect — وقتی کاربر قطع می‌شود socket.on('disconnect', () => { const user = onlineUsers.get(socket.id); if (user) { socket.to(user.room).emit('user-left', { username: user.username, message: `${user.username} اتاق را ترک کرد` }); onlineUsers.delete(socket.id); } console.log(`کاربر قطع شد: ${socket.id}`); }); }); httpServer.listen(3001, () => { console.log('Chat server روی port 3001 آماده است'); });

تفاوت emit، to، و broadcast

emit-patterns.js
// فقط به این یک socket socket.emit('event', data); // به همه به جز این socket socket.broadcast.emit('event', data); // به همه در یک room به جز این socket socket.to('roomName').emit('event', data); // به همه در یک room (شامل خودش) io.to('roomName').emit('event', data); // به همه client‌های وصل (کل سرور) io.emit('event', data); // به چند room همزمان io.to('room1').to('room2').emit('event', data);

نکات کلیدی برای مصاحبه

  • WebSocket یک اتصال دو‌طرفه دائمی است — برخلاف HTTP که request-response است.
  • Socket.io روی WebSocket ساخته شده و امکاناتی مثل Rooms، auto-reconnect و event system اضافه می‌کند.
  • Room یک گروه از socketهاست — می‌توانید به همه اعضای یک room پیام بفرستید.
  • socket.to(room) به بقیه room می‌فرستد (نه خودش). io.to(room) به همه شامل خودش.
  • برای scaling چند سرور، به Redis Adapter نیاز دارید تا socketها بین سرورها sync شوند.
  • همیشه authentication را در middleware socket.io انجام دهید — قبل از اینکه connection برقرار شود.
  • سوال رایج: «چرا Socket.io به جای WebSocket خام؟» — Socket.io قابلیت‌های آماده مثل fallback (اگر WebSocket نشد، به polling سوییچ می‌کند)، auto-reconnect، و room را رایگان می‌دهد که پیاده‌سازی دستی‌شان زمان‌بر است.
  • یک تله رایج: فراموش کردن Redis Adapter وقتی سرور با چند instance اجرا می‌شود — کاربر A روی سرور ۱ پیام کاربر B را که روی سرور ۲ است دریافت نمی‌کند.
  • WebSocket handshake با یک HTTP request شروع می‌شود (Upgrade header) و بعد به یک اتصال TCP پایدار تبدیل می‌شود — به همین دلیل هنوز به سرور HTTP نیاز دارید.
  • برای قطع اتصال کاربر، رویداد disconnect را گوش دهید — مثلاً برای پاک کردن او از لیست کاربران آنلاین.
