TypeScript
JavaScript با تایپ

TypeScript نسخه‌ای از JavaScript است که سیستم تایپ قوی به آن اضافه شده. خطاها را قبل از اجرا پیدا می‌کند، کد را خواناتر می‌کند، و با IDE خیلی بهتر کار می‌کند. امروز بیشتر پروژه‌های بزرگ Node.js با TypeScript نوشته می‌شوند.

Types Interface Generics Decorators tsconfig

چرا TypeScript؟

🐛 خطا قبل از اجرا

کامپایلر TypeScript قبل از اجرای کد، اشتباهات تایپی را پیدا می‌کند.

💡 Autocomplete بهتر

IDE می‌داند هر متغیر چه متدها و propertyهایی دارد.

📖 کد خواناتر

وقتی تابعی می‌بینید، می‌دانید چه ورودی می‌گیرد و چه خروجی می‌دهد.

🔄 Refactor راحت‌تر

وقتی نام چیزی را عوض می‌کنید، همه جا به‌روز می‌شود.

نصب و راه‌اندازی

TypeScript کدی که می‌نویسیم را به JavaScript تبدیل (compile) می‌کند. Node.js مستقیماً TypeScript نمی‌فهمد.

terminal
# نصب TypeScript npm install --save-dev typescript @types/node # ساخت فایل تنظیمات npx tsc --init # برای توسعه — اجرای مستقیم TS بدون compile npm install --save-dev ts-node nodemon # اجرا npx ts-node src/index.ts
tsconfig.json — تنظیمات مهم
{ "compilerOptions": { "target": "ES2022", // به چه نسخه JS تبدیل شود "module": "commonjs", // سیستم ماژول "outDir": "./dist", // خروجی JS کجا برود "rootDir": "./src", // کد TS کجاست "strict": true, // سخت‌گیری کامل — توصیه می‌شود "esModuleInterop": true, // import بهتر از CommonJS "resolveJsonModule": true // import فایل JSON }, "include": ["src/**/*"], "exclude": ["node_modules", "dist"] }

انواع داده (Types) پایه

در TypeScript باید نوع هر متغیر را مشخص کنید. کامپایلر بعد از آن مراقب است که اشتباه تایپی ندهید.

basic-types.ts
// انواع ابتدایی let name: string = 'Ali'; let age: number = 25; let active: boolean = true; let data: null = null; let value: undefined; // آرایه let numbers: number[] = [1, 2, 3]; let names: string[] = ['Ali', 'Sara']; let mixed: Array<string | number> = [1, 'two']; // Tuple — آرایه با طول و نوع ثابت let point: [number, number] = [10, 20]; let entry: [string, number] = ['Ali', 25]; // any — از این دوری کنید! هدف TypeScript را از بین می‌برد let anything: any = 'می‌تواند هر چیزی باشد'; // unknown — بهتر از any — باید چک کنید قبل از استفاده let unknown: unknown = fetchData(); if (typeof unknown === 'string') { console.log(unknown.toUpperCase()); // حالا مطمئنیم string است } // void — تابعی که چیزی برنمی‌گرداند function logMessage(msg: string): void { console.log(msg); } // never — تابعی که هیچ‌وقت تمام نمی‌شود function throwError(msg: string): never { throw new Error(msg); }

Interface و Type

Interface و Type برای تعریف شکل یک object استفاده می‌شوند. با آن‌ها می‌گویید «این object باید دقیقاً این شکل باشد».

interfaces.ts
// Interface — برای تعریف شکل object interface User { id: number; name: string; email: string; age?: number; // ? یعنی اختیاری readonly createdAt: Date; // فقط خواندنی } // استفاده از interface const user: User = { id: 1, name: 'Ali', email: 'ali@example.com', createdAt: new Date() }; // user.createdAt = new Date() ← Error! readonly است // Interface برای function interface CreateUser { (name: string, email: string): Promise<User>; } // Extending interface interface AdminUser extends User { permissions: string[]; role: 'admin' | 'superadmin'; // Union type — فقط این دو مقدار } // Type alias — انعطاف بیشتر از interface type Status = 'active' | 'inactive' | 'pending'; type ID = string | number; type UserOrAdmin = User | AdminUser; let status: Status = 'active'; // status = 'deleted' ← Error! این مقدار در Type نیست

Generics — کد قابل استفاده مجدد

Generics مثل یک قالب (template) هستند. می‌توانید تابع یا class بنویسید که با هر نوع داده‌ای کار کند — بدون اینکه type safety را از دست بدهید. مثل یک کارتن که می‌تواند هر چیزی داخلش باشد، ولی می‌دانید چه چیزی درش گذاشتید.

generics.ts
// بدون Generic — باید برای هر نوع یک تابع بنویسید function firstNumber(arr: number[]): number { return arr[0]; } function firstString(arr: string[]): string { return arr[0]; } // با Generic — یک تابع برای همه نوع‌ها function first<T>(arr: T[]): T { return arr[0]; } first([1, 2, 3]); // TypeScript می‌داند number برمی‌گرداند first(['a', 'b']); // TypeScript می‌داند string برمی‌گرداند // Generic با constraint — T باید id داشته باشد function findById<T extends { id: number }>( items: T[], id: number ): T | undefined { return items.find(item => item.id === id); } // Generic class — مثل یک صف عمومی class Stack<T> { private items: T[] = []; push(item: T): void { this.items.push(item); } pop(): T | undefined { return this.items.pop(); } peek(): T | undefined { return this.items[this.items.length - 1]; } get size(): number { return this.items.length; } } const numStack = new Stack<number>(); numStack.push(1); numStack.push(2); // numStack.push('hello') ← Error! فقط number قبول می‌کند

Utility Types — ابزارهای آماده

TypeScript چند نوع آماده دارد که خیلی کاربردی هستند و در Node.js زیاد استفاده می‌شوند:

utility-types.ts
interface User { id: number; name: string; email: string; password: string; age: number; } // Partial — همه fieldها اختیاری می‌شوند (برای update) type UpdateUser = Partial<User>; // { id?: number; name?: string; email?: string; ... } // Required — همه fieldها اجباری می‌شوند type RequiredUser = Required<User>; // Pick — فقط چند field خاص type PublicUser = Pick<User, 'id' | 'name' | 'email'>; // password حذف شد — امن! // Omit — همه به جز چند field type UserWithoutPassword = Omit<User, 'password'>; // Readonly — همه fieldها read-only می‌شوند type ImmutableUser = Readonly<User>; // Record — ساخت object با key/value مشخص type UserMap = Record<string, User>; const users: UserMap = { 'ali-id': { id: 1, name: 'Ali', email: 'ali@test.com', password: '...', age: 25 } };

نکات کلیدی برای مصاحبه

  • TypeScript در runtime اجرا نمی‌شود — به JavaScript compile می‌شود. Node.js فقط JS می‌فهمد.
  • از any فرار کنید! به جای آن از unknown استفاده کنید.
  • Interface برای تعریف شکل object‌ها. Type برای Union، Intersection و alias.
  • Generics کد را DRY (Don't Repeat Yourself) می‌کنند — یک بار بنویس، همه‌جا استفاده کن.
  • strict: true را همیشه روشن کنید — بیشترین مزایای TypeScript را می‌دهد.
  • Utility types مثل Pick، Omit، Partial در Node.js برای API response خیلی رایج‌اند.
  • سوال رایج: «فرق any و unknown چیست؟» — any کاملاً type-checking را خاموش می‌کند؛ unknown اجازه هر مقداری را می‌دهد ولی قبل از استفاده مجبورتان می‌کند نوعش را چک کنید، پس امن‌تر است.
  • یک تله رایج: استفاده زیاد از as (type assertion) برای «خاموش کردن» خطای کامپایلر — این کار type safety را از بین می‌برد؛ به جای آن باید type درست را تعریف کرد.
  • Interface قابل extend و merge شدن است (چند بار تعریف همان اسم با هم ترکیب می‌شوند)؛ Type این قابلیت را ندارد ولی برای union type (مثل 'a' | 'b') فقط Type کار می‌کند.
  • در پروژه‌های Node.js واقعی، معمولاً TypeScript با ts-node یا esbuild برای development استفاده می‌شود و با tsc برای build نهایی production.
