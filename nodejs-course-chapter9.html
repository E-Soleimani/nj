JS
Fundamentals

مفاهیم پایه‌ای JavaScript که در Node.js هر روز استفاده می‌شوند. چون JS می‌دانید این فصل برایتان آشناست — ولی بعضی نکات ظریف وجود دارد که در مصاحبه پرسیده می‌شود و باید دقیق بدانید.

var/let/const Scope Closure Destructuring Spread/Rest Array Methods

var، let و const — تفاوت مهم

سه روش تعریف متغیر در JS وجود دارد. var قدیمی است و مشکل دارد. امروز همیشه از const استفاده کنید، و فقط وقتی مقدار واقعاً تغییر می‌کند از let.

var-let-const.js
// ❌ var — مشکل دارد: function-scoped است نه block-scoped var x = 1; if (true) { var x = 2; // همان x بیرونی را عوض کرد! } console.log(x); // 2 — نه 1! این باگ می‌سازد // ✅ let — block-scoped، مقدار قابل تغییر let count = 0; if (true) { let count = 2; // یک count جدید فقط داخل این block } console.log(count); // 0 — درست! count = 5; // ✅ می‌توان مقدار let را عوض کرد // ✅ const — مقدار ثابت (reference ثابت است) const PI = 3.14; // PI = 3.15; ← Error! نمی‌توان reassign کرد // ⚠️ نکته مهم: const برای object یعنی reference ثابت است، نه محتوا const user = { name: 'Ali' }; user.name = 'Reza'; // ✅ مجاز — محتوای object تغییر کرد user.age = 25; // ✅ مجاز — property جدید اضافه شد // user = {}; ← Error! نمی‌توان user را به object دیگری اشاره داد // قانون ساده: همیشه const استفاده کنید // اگر reassign لازم شد، let کنید // var هیچ‌وقت!

Scope — محدوده متغیرها

Scope یعنی از کجا می‌توان یک متغیر را دید و استفاده کرد. JavaScript سه نوع scope دارد:

scope.js
// ۱. Global Scope — همه جا دیده می‌شود const appName = 'My App'; // در کل فایل قابل دسترس function greet() { // ۲. Function Scope — فقط داخل این تابع const message = 'Hello'; console.log(appName); // ✅ global دیده می‌شود console.log(message); // ✅ local دیده می‌شود } greet(); // console.log(message); ← ReferenceError! بیرون از تابع نیست if (true) { // ۳. Block Scope — فقط داخل {} (فقط با let و const) const blockVar = 'I am block scoped'; } // console.log(blockVar); ← ReferenceError! بیرون از block نیست // Scope Chain — اگر متغیر پیدا نشد، در scope بیرونی جستجو می‌کند const outer = 'من بیرونی هستم'; function outerFn() { const middle = 'من میانی هستم'; function innerFn() { const inner = 'من داخلی هستم'; console.log(inner); // ✅ پیدا شد console.log(middle); // ✅ از scope بیرونی پیدا شد console.log(outer); // ✅ از global پیدا شد } innerFn(); }

Closure — مفهوم پیشرفته ولی مهم

Closure یعنی یک تابع می‌تواند به متغیرهای scope بیرونی‌اش دسترسی داشته باشد، حتی بعد از اینکه آن scope اجرایش تمام شده. این مفهوم ظاهراً عجیب است ولی در Node.js خیلی کاربرد دارد.

تشبیه: تصور کنید یک کارخانه می‌بندد (scope تمام می‌شود) ولی یک کارگر (تابع داخلی) هنوز کلید کارخانه را دارد و می‌تواند هر وقت برگردد و به داخل دسترسی داشته باشد.

closure.js
// مثال ساده — counter با closure function makeCounter() { let count = 0; // این متغیر داخل closure "بسته" می‌شود // این object برمی‌گردد — توابع داخلی به count دسترسی دارند return { increment: () => ++count, decrement: () => --count, getCount: () => count, reset: () => { count = 0; } }; } const counter = makeCounter(); // makeCounter اجرایش تمام شد ولی count هنوز در حافظه است! counter.increment(); // 1 counter.increment(); // 2 counter.increment(); // 3 counter.decrement(); // 2 console.log(counter.getCount()); // 2 // count از بیرون قابل دسترس نیست — private است! // console.log(count); ← ReferenceError // کاربرد واقعی در Node.js — middleware با تنظیمات function createRateLimiter(maxRequests, windowMs) { const requests = new Map(); // این Map در closure بسته می‌شود return function(req, res, next) { const ip = req.ip; const now = Date.now(); const userRequests = requests.get(ip) || []; // فقط درخواست‌های اخیر را نگه دار const recentRequests = userRequests.filter(time => now - time < windowMs); if (recentRequests.length >= maxRequests) { return res.status(429).json({ error: 'Too many requests' }); } recentRequests.push(now); requests.set(ip, recentRequests); next(); }; } // maxRequests و windowMs بسته شدند داخل closure const limiter = createRateLimiter(100, 60000); app.use(limiter);

Destructuring — باز کردن آبجکت و آرایه

Destructuring یک syntax کوتاه است که به شما اجازه می‌دهد مقادیر داخل object یا آرایه را به متغیرهای جداگانه تبدیل کنید. در Node.js خیلی رایج است — مخصوصاً در import و function parameters.

destructuring.js
// Object Destructuring — بیرون کشیدن مقادیر از object const user = { name: 'Ali', age: 25, city: 'Tehran', role: 'admin' }; // روش قدیمی: const name1 = user.name; const age1 = user.age; // روش مدرن با destructuring: const { name, age } = user; console.log(name, age); // Ali 25 // rename — متغیر با نام دیگر const { name: userName, role: userRole } = user; console.log(userName, userRole); // Ali admin // مقدار پیش‌فرض — اگر property نبود const { name: n, score = 0 } = user; console.log(score); // 0 — چون user.score نداشت // Array Destructuring const colors = ['red', 'green', 'blue']; const [first, second] = colors; console.log(first, second); // red green // skip کردن عناصر const [, , third] = colors; console.log(third); // blue // Destructuring در function parameters — خیلی رایج function createUser({ name, email, role = 'user', age }) { // به جای options.name، options.email و... console.log(`Creating ${role}: ${name} (${email})`); } createUser({ name: 'Sara', email: 'sara@test.com', age: 28 }); // Creating user: Sara (sara@test.com) // Nested destructuring const response = { data: { user: { id: 1, name: 'Ali' } }, status: 200 }; const { data: { user: { id, name: respName } }, status } = response; console.log(id, respName, status); // 1 Ali 200

Spread و Rest — گسترش و جمع‌آوری

هر دو از علامت ... استفاده می‌کنند ولی کار متفاوتی انجام می‌دهند. Spread یک آرایه یا object را گسترش می‌دهد. Rest چند آرگومان را در یک آرایه جمع می‌کند.

spread-rest.js
// Spread روی آرایه — گسترش دادن const nums1 = [1, 2, 3]; const nums2 = [4, 5, 6]; const all = [...nums1, ...nums2]; // [1,2,3,4,5,6] // Spread روی object — کپی + merge const defaults = { timeout: 3000, retries: 3, method: 'GET' }; const config = { ...defaults, timeout: 5000, url: '/api/users' }; // { timeout: 5000, retries: 3, method: 'GET', url: '/api/users' } // timeout از defaults override شد // یک الگوی رایج: حذف یک key از object const userWithPass = { name: 'Ali', email: 'ali@test.com', password: 'secret' }; const { password, ...safeUser } = userWithPass; console.log(safeUser); // { name: 'Ali', email: 'ali@test.com' } — بدون password // Rest در function — جمع‌آوری باقی آرگومان‌ها function sum(...numbers) { // numbers یک آرایه است از همه آرگومان‌ها return numbers.reduce((total, n) => total + n, 0); } console.log(sum(1, 2, 3, 4, 5)); // 15

Array Methods — map، filter، reduce

این سه متد شاید پراستفاده‌ترین array methods در Node.js باشند. به جای حلقه‌های for، از این‌ها استفاده کنید — کد خواناتر می‌شود.

array-methods.js
const users = [ { id: 1, name: 'Ali', age: 25, active: true }, { id: 2, name: 'Sara', age: 30, active: false }, { id: 3, name: 'Reza', age: 22, active: true }, { id: 4, name: 'Mina', age: 28, active: true }, ]; // map — هر عنصر را تبدیل می‌کند، همان تعداد برمی‌گرداند const names = users.map(u => u.name); // ['Ali', 'Sara', 'Reza', 'Mina'] const publicUsers = users.map(u => ({ id: u.id, name: u.name })); // فقط id و name — بدون age و active // filter — فقط عناصری که شرط را دارند برمی‌گرداند const activeUsers = users.filter(u => u.active); // [Ali, Reza, Mina] const adults = users.filter(u => u.age >= 25); // [Ali, Sara, Mina] // reduce — همه عناصر را به یک مقدار تبدیل می‌کند const totalAge = users.reduce((sum, u) => sum + u.age, 0); // 25+30+22+28 = 105 // زنجیر کردن — chain methods const result = users .filter(u => u.active) // فیلتر کاربران active .map(u => u.name) // فقط نام .sort(); // مرتب‌سازی // ['Ali', 'Mina', 'Reza'] // find — اولین عنصر مطابق شرط const sara = users.find(u => u.name === 'Sara'); // some — آیا حداقل یکی شرط را دارد؟ const hasAdmin = users.some(u => u.role === 'admin'); // false // every — آیا همه شرط را دارند؟ const allActive = users.every(u => u.active); // false

Optional Chaining و Nullish Coalescing

دو operator مدرن که در Node.js برای کار با داده‌های ناقص یا undefined خیلی مفیدند:

modern-operators.js
// Optional Chaining (?.) — اگر null/undefined باشد خطا نمی‌دهد const user = { profile: { avatar: 'img.png', social: null } }; // روش قدیمی — باید چک کنید: const twitter = user && user.profile && user.profile.social && user.profile.social.twitter; // روش مدرن با ?. const twitter2 = user?.profile?.social?.twitter; // undefined — بدون خطا، حتی با social: null // فراخوانی متد اختیاری user?.profile?.getAvatar?.(); // اگر getAvatar نبود، خطا نمی‌دهد // Nullish Coalescing (??) — فقط اگر null یا undefined باشد const port = process.env.PORT ?? 3000; // اگر PORT نباشد: 3000 // اگر PORT=0 باشد: 0 (نه 3000!) // با || فرق دارد: PORT=0 با || به 3000 می‌رفت // مقایسه ?? و || console.log(0 || 10); // 10 — 0 falsy است console.log(0 ?? 10); // 0 — 0 مقدار معتبر است console.log('' || 'hi'); // hi — '' falsy است console.log('' ?? 'hi'); // '' — '' مقدار معتبر است

نکات کلیدی برای مصاحبه

  • همیشه const استفاده کنید. اگر reassign لازم بود let. هیچ‌وقت var.
  • Closure: تابعی که به متغیرهای scope بیرونی‌اش دسترسی دارد حتی بعد از اتمام آن scope.
  • Destructuring در parameters خیلی رایج است — به جای options.name می‌نویسید { name }.
  • Spread برای کپی immutable: { ...obj, key: newVal } object جدید می‌سازد — اصلی دست نخورده.
  • ?? فقط null/undefined را چک می‌کند — || همه falsy values را (0، ''، false هم).
  • map/filter/reduce زنجیر کنید — تمیزتر از حلقه‌های for تودرتو است.
  • مشکل اصلی var: scope تابعی دارد نه بلوکی، یعنی داخل یک if یا for هم تعریف شود، بیرونش هم قابل دسترسی است — همین باعث باگ‌های عجیب می‌شود.
  • سوال رایج: «closure دقیقاً چطور کار می‌کند؟» — وقتی تابعی داخل تابع دیگر تعریف می‌شود، به متغیرهای تابع بیرونی دسترسی دارد و آن‌ها را «به خاطر می‌سپارد» حتی اگر تابع بیرونی تمام شده باشد؛ کاربرد رایج: ساخت counter یا private state.
  • اپراتور ?. (optional chaining) از خطای «Cannot read property of undefined» جلوگیری می‌کند: user?.address?.city اگر هرکدام نبود، undefined برمی‌گرداند نه Error.
  • یک تله رایج: استفاده از || برای مقدار پیش‌فرض وقتی 0 یا '' مقدار معتبری است — مثلاً count || 10 اگر count برابر 0 باشد، اشتباهاً 10 برمی‌گرداند؛ اینجا باید از ?? استفاده شود.
  • Array methods مثل map/filter یک آرایه جدید می‌سازند و آرایه اصلی را تغییر نمی‌دهند (immutable) — برخلاف push/splice که آرایه اصلی را mutate می‌کنند.
