Async
Programming

برنامه‌نویسی ناهمزمان قلب Node.js است. یاد می‌گیریم سه روشی که JavaScript برای کار با async ارائه می‌دهد: Callback، Promise و async/await — و تفاوت‌ها، مشکلات و بهترین روش هر کدام.

Callback Promise async/await Promise.all Error handling

چرا Async در Node.js اهمیت دارد؟

در Node.js اکثر کارها I/O هستند: خواندن فایل، query به database، call به API خارجی. همه این کارها زمان می‌برند. اگر منتظر هر کدام بمانیم (blocking)، در آن مدت هیچ درخواست دیگری نمی‌توانیم پاسخ دهیم. Async programming به ما اجازه می‌دهد این کارها را بدون مسدود کردن thread انجام دهیم.

تشبیه رستوران: یک گارسون (thread) می‌تواند ده میز را سرویس دهد. بعد از گرفتن سفارش میز اول، می‌رود میز دوم را می‌گیرد — منتظر نمی‌ماند غذا آماده شود. وقتی غذا آماده شد، برمی‌گردد. این async است.

تکامل Async در JavaScript

ES5

Callback — روش اول (قدیمی)

تابعی که بعد از تمام شدن کار async صدا زده می‌شود. منجر به "Callback Hell" می‌شود.

ES6

Promise — روش دوم (بهتر)

یک object که نمایانگر نتیجه آینده است. زنجیر کردن با .then() کد را تمیزتر می‌کند.

ES2017

async/await — روش سوم (بهترین)

Syntax شکر روی Promise. کد async را مثل sync می‌نویسید — خواناترین روش.

روش اول: Callback

Callback یک تابع است که به عنوان آرگومان به تابع دیگری می‌دهید تا بعد از تمام شدن کار async صدا زده شود. در Node.js قراردادی وجود دارد که اول پارامتر error است، بعد نتیجه — به این error-first callback می‌گویند.

callback-pattern.js
const fs = require('fs'); // الگوی error-first callback در Node.js // اول err، بعد نتیجه — این قرارداد است fs.readFile('data.txt', 'utf8', (err, data) => { if (err) { console.error('خطا در خواندن فایل:', err.message); return; // اجرا متوقف می‌شود } console.log('محتوای فایل:', data); }); console.log('این قبل از خواندن فایل اجرا می‌شود'); // مشکل — Callback Hell (جهنم callback) // وقتی چند کار async به هم وابسته هستند: fs.readFile('users.json', 'utf8', (err, usersData) => { if (err) return console.error(err); const users = JSON.parse(usersData); db.findUser(users[0].id, (err, user) => { if (err) return console.error(err); emailService.send(user.email, 'Welcome!', (err, result) => { if (err) return console.error(err); console.log('ایمیل ارسال شد'); // اگر کار دیگری هم بود، indent بیشتری می‌شد — Callback Hell! }); }); });

روش دوم: Promise

Promise یک object است که نمایانگر نتیجه آینده یک کار async است. سه حالت دارد: pending (در انتظار)، fulfilled (موفق) و rejected (ناموفق). با .then() نتیجه موفق و با .catch() خطا را می‌گیرید.

promise-basics.js
// ساخت یک Promise function delay(ms) { return new Promise((resolve, reject) => { // resolve = موفق، reject = ناموفق setTimeout(() => resolve('تمام شد!'), ms); }); } // استفاده از Promise با .then/.catch delay(1000) .then(result => { console.log(result); // تمام شد! return delay(500); // می‌توانیم Promise جدید برگردانیم }) .then(result => { console.log('دوباره تمام شد!'); }) .catch(error => { console.error('خطا:', error); }) .finally(() => { console.log('همیشه اجرا می‌شود'); }); // مثال واقعی — fetch از API function getUser(id) { return fetch(`/api/users/${id}`) .then(response => { if (!response.ok) throw new Error('User not found'); return response.json(); }) .then(user => { console.log('کاربر:', user.name); return user; }); }

روش سوم: async/await — بهترین روش

async/await روی Promise ساخته شده — در واقع یک syntax شکر است. کد async را مثل کد sync می‌نویسید که خیلی خواناتر است. async تابع را Promise برگردان می‌کند. await منتظر می‌ماند تا Promise تمام شود.

async-await.js
// همان مثال قبل با async/await — خیلی تمیزتر async function processUser(userId) { try { // await منتظر Promise می‌ماند بدون block کردن thread const user = await db.findUser(userId); if (!user) throw new Error('کاربر پیدا نشد'); const orders = await db.findOrdersByUser(user.id); const emailResult = await emailService.send(user.email, 'خلاصه سفارشات'); console.log(`${orders.length} سفارش به ${user.email} ارسال شد`); return { user, orders }; } catch (error) { console.error('خطا در پردازش کاربر:', error.message); throw error; // دوباره throw کنید تا caller بداند } } // صدا زدن async function processUser('user-123') .then(result => console.log('موفق:', result)) .catch(err => console.error('ناموفق:', err.message));

Promise.all — کارهای موازی

گاهی چند کار async دارید که به هم وابسته نیستند. اگر آن‌ها را یکی یکی await کنید، وقت تلف می‌شود. Promise.all همه را همزمان اجرا می‌کند و منتظر می‌ماند همه تمام شوند:

promise-all.js
// ❌ روش اشتباه — ۳ ثانیه طول می‌کشد (۱+۱+۱) async function slowWay() { const user = await getUser(1); // 1 ثانیه منتظر const orders = await getOrders(1); // 1 ثانیه منتظر const reviews = await getReviews(1);// 1 ثانیه منتظر // مجموع: 3 ثانیه } // ✅ روش درست — فقط ۱ ثانیه (هر سه موازی اجرا می‌شوند) async function fastWay() { const [user, orders, reviews] = await Promise.all([ getUser(1), getOrders(1), getReviews(1) ]); // مجموع: فقط 1 ثانیه — هر سه موازی اجرا شدند console.log(user.name, orders.length, reviews.length); } // Promise.allSettled — اگر بعضی fail شوند مشکلی نیست async function safeParallel() { const results = await Promise.allSettled([ getUser(1), getUser(999), // این ممکن است fail شود getOrders(1) ]); results.forEach((result, i) => { if (result.status === 'fulfilled') { console.log(`نتیجه ${i}:`, result.value); } else { console.error(`خطا ${i}:`, result.reason.message); } }); } // Promise.race — اولین نتیجه را می‌گیرد (برای timeout مفید) async function withTimeout(promise, ms) { const timeout = new Promise((_, reject) => setTimeout(() => reject(new Error('Timeout!')), ms) ); return Promise.race([promise, timeout]); }

نکات کلیدی برای مصاحبه

  • Callback قدیمی است ولی هنوز در Node.js core APIs مثل fs دیده می‌شود. الگوی error-first را بدانید.
  • Promise سه حالت دارد: pending، fulfilled، rejected. بعد از resolve یا reject تغییر نمی‌کند.
  • async/await روی Promise ساخته شده — هر async function یک Promise برمی‌گرداند.
  • همیشه await را در try/catch بپیچید — خطاهای Promise با await مثل خطاهای sync می‌شوند.
  • Promise.all وقتی کارها مستقل از هم هستند — موازی اجرا می‌کند و سریع‌تر است.
  • Promise.allSettled وقتی می‌خواهید همه نتایج را داشته باشید حتی اگر بعضی fail شوند.
  • سوال رایج: «چرا Promise.all بهتر از چند await پشت سر هم است؟» — چند await جدا یعنی هر کدام منتظر قبلی می‌ماند (ترتیبی)؛ Promise.all همه را همزمان شروع می‌کند، پس اگر مستقل باشند، خیلی سریع‌تر تمام می‌شود.
  • یک تله رایج: در حلقه از forEach با async استفاده کردن — forEach منتظر Promiseها نمی‌ماند؛ برای اجرای ترتیبی باید از for...of با await استفاده کرد.
  • Promise.race اولین Promise‌ای که تمام شود (چه موفق چه ناموفق) را برمی‌گرداند — کاربرد رایج: پیاده‌سازی timeout برای یک درخواست.
  • error-first callback یعنی اولین پارامتر callback همیشه خطا است (یا null اگر خطایی نبود) — قرارداد قدیمی Node.js قبل از رواج Promise.
