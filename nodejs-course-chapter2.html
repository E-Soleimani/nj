توسعه روی
Linux

یاد می‌گیریم چطور Node.js را روی Linux نصب کنیم، با terminal کار کنیم، متغیرهای محیطی را مدیریت کنیم، و برنامه‌مان را به درستی اجرا کنیم. اکثر سرورهای دنیا Linux هستند — پس باید با آن راحت باشیم.

Terminal NVM Environment Variables PM2 nodemon

چرا Linux برای Node.js؟

وقتی یک اپلیکیشن Node.js را روی سرور deploy می‌کنید، آن سرور تقریباً همیشه Linux است. اگر روی Windows توسعه دهید و روی Linux deploy کنید، ممکن است با مشکلاتی مثل تفاوت path، permission و package برخورد کنید. به همین دلیل توسعه‌دهندگان حرفه‌ای ترجیح می‌دهند از همان ابتدا روی Linux کار کنند.

💡

اگر Windows دارید چی؟ نگران نباشید! WSL2 (Windows Subsystem for Linux) نصب کنید. یک Ubuntu واقعی داخل Windows به شما می‌دهد — بدون نیاز به dual boot یا ماشین مجازی. از Microsoft Store نصب می‌شود.

نصب Node.js با NVM — روش درست

خیلی‌ها اشتباه می‌کنند و Node.js را مستقیم با apt install nodejs نصب می‌کنند. این روش چند مشکل دارد: نسخه قدیمی نصب می‌شود، برای تغییر نسخه باید همه چیز را پاک کنید، و برای نصب پکیج‌های global نیاز به sudo دارید که خطرناک است.

راه‌حل: NVM (Node Version Manager) — یک ابزار که چند نسخه Node را همزمان مدیریت می‌کند و می‌توانید بین آن‌ها سوئیچ کنید. مثل اینکه چند نسخه Python داشته باشید.

۱

نصب NVM

این دستور اسکریپت نصب را دانلود و اجرا می‌کند. بعد از اجرا، ترمینال را ببندید و دوباره باز کنید:

terminal
# دانلود و اجرای اسکریپت نصب NVM curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash # بعد از بسته و باز کردن ترمینال، چک کنید: nvm --version # باید عددی مثل 0.39.7 نشان دهد
۲

نصب Node.js LTS

LTS مخفف Long Term Support است — نسخه‌ای که چند سال پشتیبانی می‌شود. برای production همیشه LTS انتخاب کنید:

terminal
# نصب آخرین نسخه LTS nvm install --lts # یا نصب نسخه خاص nvm install 20 nvm install 18 # فعال کردن نسخه nvm use 20 # تنظیم نسخه پیش‌فرض — هر بار ترمینال باز شود nvm alias default 20 # تأیید نصب node --version # باید v20.x.x نشان دهد npm --version # باید 10.x.x نشان دهد
۳

کار با چند نسخه

فرض کنید یک پروژه قدیمی روی Node 16 کار می‌کند و یک پروژه جدید روی Node 20. با NVM راحت بین آن‌ها جابجا می‌شوید:

terminal
# لیست نسخه‌های نصب شده روی سیستم nvm list # سوئیچ به نسخه دیگر nvm use 18 node --version # v18.x.x nvm use 20 node --version # v20.x.x # فایل .nvmrc در پروژه — نسخه را fix می‌کند echo "20" > .nvmrc nvm use # خودکار نسخه را از .nvmrc می‌خواند

دستورات ضروری Terminal

به عنوان یک توسعه‌دهنده Node.js، این دستورات را باید در خواب هم بلد باشید. هر روز استفاده می‌شوند:

ناوبری در فایل‌ها

pwd

نشان می‌دهد الان در کدام پوشه هستید (Print Working Directory)

ls -la

لیست همه فایل‌ها با جزئیات — حتی فایل‌های مخفی که با . شروع می‌شوند

cd projects/myapp

رفتن به پوشه مشخص. cd .. برای برگشتن به پوشه بالاتر

mkdir -p src/utils

ساخت پوشه جدید. p- یعنی اگر پوشه والد نبود هم بساز

touch index.js

ساختن یک فایل خالی جدید

rm -rf node_modules

حذف کامل پوشه. r- یعنی recursive، f- یعنی بدون سوال

cp -r src/ backup/

کپی پوشه src به backup. r- برای کپی recursive

cat package.json

نمایش محتوای یک فایل در ترمینال

پروسه‌ها و پورت‌ها

وقتی سرور Node.js اجرا می‌کنید، باید بتوانید وضعیت آن را بررسی کنید:

lsof -i :3000

کدام برنامه روی پورت 3000 در حال اجرا است؟ وقتی خطای "port in use" می‌گیرید استفاده کنید

kill -9 PID

کشتن یک پروسه با شماره آن. PID را از دستور lsof پیدا کنید

ps aux | grep node

لیست همه پروسه‌های node در حال اجرا

Ctrl + C

متوقف کردن برنامه‌ای که در terminal در حال اجرا است

متغیرهای محیطی — Environment Variables

فرض کنید در کدتان می‌نویسید: const dbPassword = 'mypassword123'. اگر این کد را روی GitHub بگذارید، همه رمز دیتابیس‌تان را می‌بینند! یا اگر بخواهید در سرور production از رمز دیگری استفاده کنید، باید کد را تغییر دهید.

راه‌حل: Environment Variables — متغیرهایی که خارج از کد تعریف می‌شوند. کد می‌خواند، ولی داخل کد نوشته نمی‌شوند. در هر محیط (dev، production) مقدار متفاوت دارند.

قانون طلایی: هر چیزی که بین محیط‌های مختلف فرق می‌کند (رمزها، آدرس‌ها، کلیدهای API) باید Environment Variable باشد — نه داخل کد.

.env — فایل متغیرهای محیطی
# این فایل را در root پروژه بسازید # هیچ‌وقت این فایل را commit نکنید! PORT=3000 NODE_ENV=development # آدرس دیتابیس DB_URL=mongodb://localhost:27017/myapp DB_PASSWORD=super-secret-password # کلیدهای خارجی JWT_SECRET=my-jwt-secret-key-very-long STRIPE_API_KEY=sk_test_abc123 SENDGRID_API_KEY=SG.xyz789
server.js — خواندن متغیرها
// dotenv فایل .env را می‌خواند و متغیرها را به process.env اضافه می‌کند // نصب: npm install dotenv require('dotenv').config(); // حالا از process.env می‌خوانیم const port = process.env.PORT || 3000; // اگر نبود، 3000 پیش‌فرض const dbUrl = process.env.DB_URL; const isProd = process.env.NODE_ENV === 'production'; const jwtKey = process.env.JWT_SECRET; // چک کردن اینکه متغیرهای ضروری وجود دارند if (!jwtKey) { console.error('❌ JWT_SECRET تعریف نشده!'); process.exit(1); // برنامه را متوقف کن } console.log(`✅ Server on port ${port} | env: ${process.env.NODE_ENV}`);
⚠️

مهم: فایل .env را به .gitignore اضافه کنید تا commit نشود. به جایش یک فایل .env.example بسازید که نام متغیرها را دارد ولی مقادیر واقعی ندارد. این را commit کنید تا همکارها بدانند چه متغیرهایی نیاز است.

.env.example — این را commit کنید
PORT=3000 NODE_ENV=development DB_URL=mongodb://localhost:27017/yourapp DB_PASSWORD=your-db-password-here JWT_SECRET=your-jwt-secret-here STRIPE_API_KEY=your-stripe-key-here

اجرای Node.js — سه روش

روش ۱ — node مستقیم (ساده‌ترین)

برای تست سریع استفاده کنید. هر بار که فایل را تغییر می‌دهید، باید دستی restart کنید:

terminal
node server.js # هر بار که کد تغییر کند باید Ctrl+C بزنید و دوباره اجرا کنید

روش ۲ — nodemon (برای Development)

nodemon فایل‌های پروژه را watch می‌کند. هر بار که فایلی تغییر کند، سرور را خودکار restart می‌کند. در توسعه خیلی راحت‌تر است:

terminal
# نصب nodemon فقط برای development npm install --save-dev nodemon # اجرا npx nodemon server.js # حالا هر بار فایل ذخیره شود، سرور restart می‌شود
package.json — scripts
{ "scripts": { "start": "node server.js", "dev": "nodemon server.js", "test": "jest" } } // حالا می‌توانید بنویسید: // npm run dev ← توسعه با auto-restart // npm start ← production

روش ۳ — PM2 (برای Production)

وقتی برنامه crash می‌کند، باید خودکار دوباره اجرا شود. وقتی سرور restart می‌شود، برنامه باید خودکار شروع به کار کند. PM2 این کارها را برای شما انجام می‌دهد:

terminal — PM2
# نصب global npm install -g pm2 # شروع برنامه pm2 start server.js --name my-app # وضعیت همه برنامه‌ها pm2 list # لاگ‌های زنده pm2 logs my-app # مانیتور CPU و Memory pm2 monit # restart و stop pm2 restart my-app pm2 stop my-app # تنظیم autostart بعد از reboot سرور pm2 startup pm2 save

نکات کلیدی برای مصاحبه

  • همیشه از NVM استفاده کنید — نه apt install. مدیریت نسخه‌ها خیلی راحت‌تر است.
  • هیچ‌وقت رمز، کلید API یا اطلاعات حساس را داخل کد ننویسید — از .env استفاده کنید.
  • فایل .env را به .gitignore اضافه کنید. فایل .env.example را commit کنید.
  • در development از nodemon استفاده کنید، در production از PM2.
  • lsof -i :3000 وقتی خطای "port already in use" می‌گیرید استفاده کنید.
  • process.env.NODE_ENV تعیین می‌کند برنامه در چه محیطی است: development یا production.
  • چرا Linux؟ چون سرورهای واقعی تقریباً همیشه لینوکس هستند؛ عادت کردن به ترمینال از همان اول لازم است.
  • با NVM می‌توانید چند نسخه Node را کنار هم نگه دارید و بین آن‌ها سوییچ کنید — مثلاً پروژه قدیمی روی نسخه ۱۶، پروژه جدید روی ۲۰.
  • nodemon فقط برای توسعه است: با هر تغییر فایل، سرور را خودش ری‌استارت می‌کند. در production استفاده نشود چون برای کار واقعی طراحی نشده.
  • PM2 در production کاربردش فقط اجرا نیست: اگر برنامه crash کند، خودش دوباره بالا می‌آورد؛ لاگ‌ها را هم مدیریت می‌کند.
  • یک تله رایج: فراموش کردن .env در .gitignore. اگر یک بار .env را commit کنید، حتی با حذفش، رمزها در تاریخچه Git می‌مانند — باید کل تاریخچه پاک شود یا رمزها عوض شوند.
  • سوال رایج: «فرق nodemon و PM2 چیست؟» — nodemon فقط auto-restart موقع تغییر کد است (برای dev)؛ PM2 یک process manager کامل است با auto-restart بعد از crash، cluster mode، و مدیریت لاگ (برای production).
