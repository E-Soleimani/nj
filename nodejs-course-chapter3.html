NPM و
نوشتن ماژول‌ها

یاد می‌گیریم چطور پکیج‌ها را مدیریت کنیم، package.json را بشناسیم، و کد خودمان را به صورت ماژول بنویسیم که در بخش‌های مختلف پروژه قابل استفاده باشد.

npm package.json CommonJS ES Modules require / import

NPM چیست؟

NPM (Node Package Manager) ابزار مدیریت پکیج Node.js است. با آن می‌توانید هزاران کتابخانه آماده را نصب کنید. مثلاً به جای اینکه خودتان یک سیستم احراز هویت بنویسید، یک پکیج آماده نصب می‌کنید.

امروز بیش از ۲ میلیون پکیج در NPM وجود دارد. تقریباً هر کاری که بخواهید انجام دهید، کسی قبلاً آن را نوشته و منتشر کرده.

تشبیه ساده: NPM مثل یک فروشگاه نرم‌افزار است. به جای اینکه خودتان همه چیز را از صفر بسازید، از این فروشگاه ابزار آماده می‌گیرید و روی پروژه‌تان نصب می‌کنید.

دستورات پرکاربرد NPM

terminal — دستورات npm
# ساختن پروژه جدید — فایل package.json می‌سازد npm init # سوال به سوال می‌پرسد npm init -y # سریع با مقادیر پیش‌فرض # نصب پکیج — به dependencies اضافه می‌شود (لازم در production) npm install express npm install mongoose dotenv # نصب پکیج فقط برای development — به devDependencies اضافه می‌شود npm install --save-dev jest nodemon typescript # نصب global — روی کل سیستم (نه فقط این پروژه) npm install -g pm2 # حذف پکیج npm uninstall express # نصب همه پکیج‌های package.json (وقتی پروژه clone می‌کنید) npm install # مشاهده پکیج‌های قدیمی npm outdated # اجرای scripts تعریف‌شده در package.json npm run dev npm start npm test

package.json — شناسنامه پروژه

هر پروژه Node.js یک فایل package.json دارد. این فایل همه اطلاعات پروژه را نگه می‌دارد: نام، نسخه، وابستگی‌ها، و اسکریپت‌هایی که می‌توانید اجرا کنید. وقتی پروژه را به GitHub می‌گذارید، این فایل به همکارها می‌گوید چه پکیج‌هایی باید نصب کنند.

package.json — توضیح کامل
{ "name": "my-node-app", // نام پروژه — باید lowercase و بدون فاصله باشد "version": "1.0.0", // نسخه پروژه (SemVer) "description": "My awesome app", "main": "index.js", // فایلی که با require('./my-package') لود می‌شود "scripts": { "start": "node index.js", // npm start "dev": "nodemon index.js", // npm run dev "test": "jest", // npm test "build": "tsc" // npm run build }, "dependencies": { // پکیج‌های لازم در production "express": "^4.18.2", "mongoose": "^8.0.0", "dotenv": "^16.0.0" }, "devDependencies": { // فقط برای توسعه — در production نصب نمی‌شوند "jest": "^29.0.0", "nodemon": "^3.0.0", "typescript": "^5.0.0" }, "engines": { "node": ">=18.0.0" // حداقل نسخه Node که لازم است } }
💡

تفاوت dependencies و devDependencies: وقتی سرور production را آماده می‌کنید، با دستور npm install --production فقط dependencies نصب می‌شوند — devDependencies نه. این حجم نصب را کمتر می‌کند.

ماژول چیست؟

در Node.js هر فایل یک ماژول است. ماژول یعنی یک قطعه کد که کار مشخصی انجام می‌دهد و می‌توانید آن را در جاهای مختلف پروژه استفاده کنید. مثلاً یک فایل برای ارتباط با دیتابیس، یک فایل برای validation، یک فایل برای ارسال ایمیل.

ایده اصلی: به جای یک فایل ۵۰۰۰ خطی، کد را به ماژول‌های کوچک تقسیم کنید که هر کدام یک مسئولیت دارند. این کد را خواناتر، قابل تست‌تر و نگهداری‌پذیرتر می‌کند.

دو سیستم ماژول در Node.js

Node.js دو روش برای import/export دارد. باید هر دو را بشناسید:

CommonJS (CJS) — قدیمی

روش اصلی Node.js از ابتدا. هنوز در اکثر پروژه‌ها استفاده می‌شود. با .js کار می‌کند.

require() / module.exports

ES Modules (ESM) — مدرن

همان چیزی که در browser و TypeScript استفاده می‌شود. در Node.js از نسخه 12 پشتیبانی می‌شود.

import / export

CommonJS — با مثال کامل

در CommonJS، هر چیزی که می‌خواهید بیرون از فایل در دسترس باشد را export می‌کنید:

src/utils/math.js — تعریف ماژول
// تعریف توابع — اینها فقط داخل این فایل هستند function add(a, b) { return a + b; } function subtract(a, b) { return a - b; } function multiply(a, b) { return a * b; } const PI = 3.14159; // module.exports — چه چیزی بیرون قابل دسترس باشد // هر چیزی که اینجا نگذارید، private است و از بیرون دیده نمی‌شود module.exports = { add, subtract, multiply, PI };
src/app.js — استفاده از ماژول
// require با ./ یا ../ یعنی فایل خودتان const { add, subtract, PI } = require('./utils/math'); // require بدون ./ یعنی پکیج npm یا ماژول built-in Node const fs = require('fs'); // built-in Node.js const path = require('path'); // built-in Node.js const express = require('express'); // پکیج npm console.log(add(5, 3)); // 8 console.log(subtract(10, 4)); // 6 console.log(PI); // 3.14159

ES Modules — روش مدرن

برای استفاده از ES Modules در Node.js، یا فایل را با پسوند .mjs بسازید، یا در package.json بنویسید "type": "module":

math.mjs — export
// Named exports — می‌توانید چندتا داشته باشید export function add(a, b) { return a + b; } export function subtract(a, b) { return a - b; } export const PI = 3.14159; // Default export — فقط یکی می‌توانید داشته باشید export default function multiply(a, b) { return a * b; }
app.mjs — import
// Named import — همان نامی که export شده import { add, subtract, PI } from './math.mjs'; // Default import — هر نامی می‌توانید بدهید import multiply from './math.mjs'; // همه را با یک نام import کنید import * as MathUtils from './math.mjs'; // ماژول‌های built-in Node — پیشوند node: توصیه می‌شود import { readFile, writeFile } from 'node:fs/promises'; import path from 'node:path';

مثال واقعی — ساختن یک ماژول Logger

در پروژه‌های واقعی، به جای console.log معمولی، یک logger می‌سازیم که timestamp، رنگ، و سطح خطا (info، warn، error) نشان دهد:

src/utils/logger.js
// کدهای رنگ برای terminal const colors = { reset: '\x1b[0m', green: '\x1b[32m', yellow: '\x1b[33m', red: '\x1b[31m', cyan: '\x1b[36m', }; // این تابع یک پیام فرمت‌شده می‌سازد function formatMessage(level, color, message) { const timestamp = new Date().toISOString(); // مثل: 2024-01-15T10:30:00.000Z return `${color}[${timestamp}] [${level}]${colors.reset} ${message}`; } // ماژول logger — شامل سه سطح const logger = { // info — اطلاعات عادی info(message) { console.log(formatMessage('INFO', colors.cyan, message)); }, // warn — هشدار — چیزی اشتباه نیست ولی باید توجه کنید warn(message) { console.warn(formatMessage('WARN', colors.yellow, message)); }, // error — خطا — چیزی اشتباه پیش رفته error(message) { console.error(formatMessage('ERROR', colors.red, message)); }, }; module.exports = logger;
src/server.js — استفاده از logger
const logger = require('./utils/logger'); logger.info('Server started on port 3000'); logger.warn('Memory usage is above 80%'); logger.error('Database connection failed'); // خروجی در terminal: // [2024-01-15T10:30:00.000Z] [INFO] Server started on port 3000 // [2024-01-15T10:30:00.001Z] [WARN] Memory usage is above 80% // [2024-01-15T10:30:00.002Z] [ERROR] Database connection failed

ساختار پوشه‌بندی پروژه حرفه‌ای

یک پروژه Node.js خوب، ساختار مشخصی دارد. هر پوشه مسئولیت خاصی دارد:

ساختار پروژه
my-project/ ├── src/ │ ├── controllers/ ← درخواست HTTP را دریافت می‌کنند │ │ └── userController.js │ ├── services/ ← منطق اصلی برنامه (business logic) │ │ └── userService.js │ ├── models/ ← ساختار داده و ارتباط با دیتابیس │ │ └── User.js │ ├── routes/ ← آدرس‌های URL و متصل کردن به controller │ │ └── userRoutes.js │ ├── middleware/ ← توابعی که بین درخواست و پاسخ اجرا می‌شوند │ │ └── auth.js │ └── utils/ ← توابع کمکی که همه جا استفاده می‌شوند │ └── logger.js ├── tests/ ← تست‌های خودکار ├── .env ← متغیرهای محیطی (commit نکنید!) ├── .env.example ← نمونه (commit کنید) ├── .gitignore ├── package.json └── index.js ← نقطه شروع برنامه

نکات کلیدی برای مصاحبه

  • dependencies در production لازم است. devDependencies فقط در توسعه — مثل jest، nodemon، typescript.
  • فایل package-lock.json را همیشه commit کنید — نسخه دقیق پکیج‌ها را قفل می‌کند تا همه یکسان باشند.
  • پوشه node_modules را هیچ‌وقت commit نکنید — سنگین است و از package.json می‌توان rebuild کرد.
  • تفاوت CJS و ESM: در CJS از require()، در ESM از import استفاده می‌کنید. در TypeScript ESM رایج‌تر است.
  • npx یک پکیج را بدون نصب global اجرا می‌کند: npx create-react-app myapp
  • هر فایل در Node.js یک ماژول است — کد داخلش به‌طور پیش‌فرض خصوصی است، فقط با export بیرون می‌رود.
  • require() نتیجه‌اش را cache می‌کند: اگر یک فایل را چند بار import کنید، فقط یک بار واقعاً اجرا می‌شود.
  • سوال رایج: «فرق require و import چیست؟» — require synchronous است و در هر جای کد قابل صدا زدن؛ import باید بالای فایل باشد ولی امکاناتی مثل tree-shaking و static analysis بهتر دارد.
  • عدد داخل package.json مثل "^4.18.2" با npm install می‌تواند نسخه بالاتر (مثل 4.19.0) نصب کند — برای همین package-lock.json مهم است، چون نسخه دقیق را ثابت نگه می‌دارد.
  • یک تله رایج: فکر نکنید حذف node_modules خطرناک است — کاملاً امن است، با npm install از روی package.json دوباره ساخته می‌شود.
  • ساختار پوشه‌بندی خوب (routes، controllers، services، models جدا) خوانایی پروژه را بالا می‌برد و برای تیم‌های بزرگ ضروری است.
