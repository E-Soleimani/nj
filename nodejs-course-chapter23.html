NestJS
Framework حرفه‌ای

NestJS همه چیزهایی که در فصل قبل یاد گرفتیم (DI، IoC، Decorator) را در یک framework کامل پیاده‌سازی کرده. در این فصل پایانی، یک ماژول کامل با Controller، Service و Module می‌سازیم.

Module Controller Service DTO Pipes Guards

NestJS چیست؟

NestJS یک framework روی Node.js است که از TypeScript و معماری Angular الهام گرفته. در حالی که Express و Fastify به شما آزادی کامل می‌دهند، NestJS یک ساختار مشخص تحمیل می‌کند — این برای تیم‌های بزرگ که نظم لازم دارند، عالی است.

چرا یاد بگیریم؟ شرکت‌های بزرگ بیشتر و بیشتر به NestJS روی می‌آورند چون structured است. اگر Express/Fastify را خوب بدانید، یادگیری NestJS راحت است — چون مفاهیمش (Controller، Service) را قبلاً دستی پیاده کرده‌اید.

سه بلوک اصلی NestJS

@Module()

گروه‌بندی کد مرتبط — مثل یک پوشه domain (users، orders). هر ماژول controllerها و serviceهای خودش را دارد.

@Controller()

دریافت HTTP request و فرستادن response. منطق تجاری اینجا نیست — فقط routing و delegation.

@Injectable() (Service)

منطق اصلی برنامه — business logic. به database یا سرویس‌های دیگر دسترسی دارد.

DTO (Data Transfer Object)

تعریف شکل دقیق داده ورودی/خروجی. با class-validator اعتبارسنجی خودکار می‌شود.

HTTP Request
↓
@Controller — دریافت request
↓
@Injectable Service — business logic
↓
Repository / Database

یک ماژول کامل بسازیم — Users

۱. DTO — تعریف شکل داده

users/dto/create-user.dto.ts
import { IsEmail, IsString, MinLength, IsOptional, IsInt, Min } from 'class-validator'; // class-validator خودکار اعتبارسنجی می‌کند export class CreateUserDto { @IsString() @MinLength(2) name: string; @IsEmail({}, { message: 'ایمیل نامعتبر است' }) email: string; @IsString() @MinLength(8) password: string; @IsOptional() @IsInt() @Min(18) age?: number; }

۲. Service — منطق اصلی

users/users.service.ts
import { Injectable, NotFoundException, ConflictException } from '@nestjs/common'; import { CreateUserDto } from './dto/create-user.dto'; // @Injectable — به NestJS می‌گوید این class می‌تواند inject شود @Injectable() export class UsersService { // در constructor، NestJS خودکار UserModel را inject می‌کند constructor( @InjectModel('User') private userModel: Model<User> ) {} async create(dto: CreateUserDto) { const existing = await this.userModel.findOne({ email: dto.email }); if (existing) { throw new ConflictException('این ایمیل قبلاً ثبت شده'); } return this.userModel.create(dto); } async findAll() { return this.userModel.find().select('-password'); } async findOne(id: string) { const user = await this.userModel.findById(id).select('-password'); if (!user) { throw new NotFoundException(`کاربر با id ${id} پیدا نشد`); // NestJS خودکار این را به HTTP 404 تبدیل می‌کند! } return user; } }

۳. Controller — دریافت HTTP Request

users/users.controller.ts
import { Controller, Get, Post, Body, Param, UseGuards } from '@nestjs/common'; import { UsersService } from './users.service'; import { CreateUserDto } from './dto/create-user.dto'; import { AuthGuard } from '../auth/auth.guard'; // @Controller('users') — همه routeهای این class با /users شروع می‌شوند @Controller('users') export class UsersController { // NestJS خودکار UsersService را اینجا inject می‌کند constructor(private readonly usersService: UsersService) {} // GET /users @Get() findAll() { return this.usersService.findAll(); } // GET /users/:id @Get(':id') findOne(@Param('id') id: string) { return this.usersService.findOne(id); } // POST /users — body خودکار validate می‌شود طبق DTO @Post() create(@Body() dto: CreateUserDto) { // اگر dto نامعتبر باشد، NestJS قبل از رسیدن به اینجا 400 می‌دهد return this.usersService.create(dto); } // روت محافظت‌شده — فقط با token معتبر @UseGuards(AuthGuard) @Get('me/profile') getProfile(@Request() req) { return req.user; } }

۴. Module — یکپارچه کردن همه چیز

users/users.module.ts
import { Module } from '@nestjs/common'; import { UsersController } from './users.controller'; import { UsersService } from './users.service'; @Module({ controllers: [UsersController], // controllerهای این ماژول providers: [UsersService], // serviceهایی که قابل inject‌اند exports: [UsersService] // به ماژول‌های دیگر هم در دسترس باشد }) export class UsersModule {}
app.module.ts — ماژول اصلی
import { Module } from '@nestjs/common'; import { UsersModule } from './users/users.module'; import { OrdersModule } from './orders/orders.module'; @Module({ imports: [UsersModule, OrdersModule] // همه ماژول‌های feature اینجا }) export class AppModule {}

Guards — محافظت از Route

Guard قبل از رسیدن به controller اجرا می‌شود و تصمیم می‌گیرد آیا اجازه دسترسی دارید یا نه — مثل middleware ولی استانداردتر:

auth/auth.guard.ts
import { Injectable, CanActivate, ExecutionContext, UnauthorizedException } from '@nestjs/common'; @Injectable() export class AuthGuard implements CanActivate { async canActivate(context: ExecutionContext): Promise<boolean> { const request = context.switchToHttp().getRequest(); const token = request.headers.authorization?.replace('Bearer ', ''); if (!token) { throw new UnauthorizedException('Token لازم است'); } try { request.user = await this.verifyToken(token); return true; // اجازه دسترسی } catch { return false; // رد دسترسی — NestJS خودکار 403 می‌دهد } } }

نکات کلیدی برای مصاحبه

  • NestJS از TypeScript و Decorator استفاده می‌کند — DI و IoC به صورت built-in.
  • Module کد را گروه‌بندی می‌کند — هر domain (users، orders) ماژول خودش را دارد.
  • Controller فقط routing — منطق در Service است (Single Responsibility).
  • DTO + class-validator اعتبارسنجی خودکار body — بدون کد دستی.
  • Guard برای authorization — قبل از controller اجرا می‌شود.
  • پرتاب NotFoundException, ConflictException خودکار به HTTP status code تبدیل می‌شود.
  • سوال رایج: «فرق Guard و Middleware در NestJS چیست؟» — Middleware زودتر اجرا می‌شود و به route اطلاعی ندارد؛ Guard دقیقاً می‌داند کدام controller/handler صدا زده شده و برای authorization دقیق‌تر است.
  • یک تله رایج: نوشتن منطق تجاری داخل Controller — Controller فقط باید درخواست را به Service پاس بدهد؛ تست کردن منطق تجاری داخل Controller سخت‌تر است.
  • ترتیب اجرای NestJS: Middleware → Guard → Interceptor (قبل) → Pipe → Controller Handler → Interceptor (بعد) → Exception Filter (اگر خطا رخ دهد).
  • در NestJS، هر Service با @Injectable() علامت‌گذاری می‌شود تا IoC Container بتواند خودکار آن را در جای دیگر تزریق کند.
