Web Server با
Fastify

Fastify یکی از سریع‌ترین و مدرن‌ترین web frameworkهای Node.js است. در این فصل یاد می‌گیریم چطور یک REST API کامل با Fastify بسازیم — از روتینگ و middleware تا validation و authentication.

Fastify REST API Routes Plugins Schema Validation Hooks

Fastify چیست؟ چرا نه Express؟

Express قدیمی‌ترین و معروف‌ترین framework است ولی قدیمی شده. Fastify با در نظر گرفتن مشکلات Express از صفر نوشته شده:

Express — قدیمی‌تر

✓ محبوب‌ترین، منابع آموزشی زیاد

✗ کند‌تر نسبت به Fastify

✗ validation داخلی ندارد

✗ TypeScript support ضعیف‌تر

Fastify — مدرن

✓ ۲ تا ۳ برابر سریع‌تر از Express

✓ Schema validation داخلی (JSON Schema)

✓ TypeScript support عالی

✓ Plugin system قوی

چرا Fastify انتخاب این دوره است؟ چون مدرن است، سریع است، و الگوهای خوبی را force می‌کند. اگر Express یاد بگیرید، Fastify هم راحت می‌فهمید — ولی برعکسش سخت‌تر است.

نصب و اولین سرور

terminal
npm init -y npm install fastify npm install --save-dev nodemon
src/server.js — اولین Fastify سرور
const fastify = require('fastify')({ logger: true }); // logger: true — لاگ‌های خودکار برای هر request // تعریف یک route ساده fastify.get('/', async (request, reply) => { // request: اطلاعات درخواست (body، params، query، headers) // reply: برای فرستادن پاسخ return { message: 'سلام از Fastify!', status: 'ok' }; // Fastify خودکار JSON.stringify می‌کند }); // شروع سرور const start = async () => { try { await fastify.listen({ port: 3000, host: '0.0.0.0' }); console.log('سرور روی http://localhost:3000 آماده است'); } catch (err) { fastify.log.error(err); process.exit(1); } }; start();

HTTP Methods و Route Patterns

در REST API هر عملیات با یک HTTP method مشخص می‌شود. این قراردادی است که همه باید رعایت کنند:

GET POST PUT PATCH DELETE
routes/users.js — CRUD کامل
// GET /users — گرفتن همه کاربران fastify.get('/users', async (request, reply) => { const { page = 1, limit = 10 } = request.query; // query params const users = await userService.getAll({ page, limit }); return { data: users, page, limit }; }); // GET /users/:id — گرفتن یک کاربر با ID fastify.get('/users/:id', async (request, reply) => { const { id } = request.params; // params از URL const user = await userService.getById(id); if (!user) return reply.code(404).send({ error: 'User not found' }); return user; }); // POST /users — ساخت کاربر جدید fastify.post('/users', async (request, reply) => { const { name, email, password } = request.body; // body از JSON const user = await userService.create({ name, email, password }); return reply.code(201).send(user); // 201 = Created }); // PUT /users/:id — آپدیت کامل fastify.put('/users/:id', async (request, reply) => { const user = await userService.update(request.params.id, request.body); return user; }); // PATCH /users/:id — آپدیت جزئی fastify.patch('/users/:id', async (request, reply) => { const user = await userService.partialUpdate(request.params.id, request.body); return user; }); // DELETE /users/:id — حذف fastify.delete('/users/:id', async (request, reply) => { await userService.delete(request.params.id); return reply.code(204).send(); // 204 = No Content });

Schema Validation — اعتبارسنجی خودکار

یکی از قوی‌ترین ویژگی‌های Fastify Schema Validation است. با تعریف schema، Fastify خودکار ورودی‌ها را اعتبارسنجی می‌کند و اگر اشتباه باشد، خطای 400 با پیام دقیق برمی‌گرداند — بدون کد اضافی:

routes/users-with-schema.js
// Schema برای POST /users const createUserSchema = { body: { type: 'object', required: ['name', 'email', 'password'], properties: { name: { type: 'string', minLength: 2, maxLength: 50 }, email: { type: 'string', format: 'email' }, password: { type: 'string', minLength: 8 }, age: { type: 'integer', minimum: 18 } }, additionalProperties: false // فیلد اضافه قبول نمی‌شود }, // response schema — تعیین می‌کند چه چیزی به client برگردد response: { 201: { type: 'object', properties: { id: { type: 'string' }, name: { type: 'string' }, email: { type: 'string' } // password اینجا نیست — خودکار filter می‌شود! } } } }; fastify.post('/users', { schema: createUserSchema }, async (request, reply) => { // اگر body اشتباه باشد، Fastify قبل از رسیدن به اینجا خطا می‌دهد const user = await userService.create(request.body); return reply.code(201).send(user); });

Hooks — اجرای کد قبل/بعد از Route

Hook یعنی یک تابع که در یک نقطه خاص از چرخه درخواست اجرا می‌شود. مثلاً قبل از هر route می‌خواهیم token را چک کنیم:

hooks/auth.js
// onRequest — اولین hook، قبل از همه چیز اجرا می‌شود fastify.addHook('onRequest', async (request, reply) => { const token = request.headers.'authorization'?.replace('Bearer ', ''); if (!token) { return reply.code(401).send({ error: 'Token required' }); } try { request.user = await jwt.verify(token); } catch { return reply.code(401).send({ error: 'Invalid token' }); } }); // preHandler — بعد از parsing body، قبل از handler fastify.addHook('preHandler', async (request, reply) => { console.log(`${request.method} ${request.url} — کاربر: ${request.user?.id}`); }); // onSend — قبل از فرستادن پاسخ — می‌توانید header اضافه کنید fastify.addHook('onSend', async (request, reply, payload) => { reply.header('X-Response-Time', `${Date.now() - request.startTime}ms`); return payload; // باید payload را برگردانید });

Plugin System — سازماندهی کد

Fastify از یک Plugin System قوی استفاده می‌کند. هر plugin یک تابع است که به fastify instance دسترسی دارد. با این روش می‌توانید کد را به بخش‌های مستقل تقسیم کنید:

plugins/users.js
const fp = require('fastify-plugin'); // npm install fastify-plugin async function usersPlugin(fastify, options) { // همه routeهای users اینجا fastify.get('/users', userHandlers.getAll); fastify.get('/users/:id', userHandlers.getById); fastify.post('/users', userHandlers.create); } module.exports = fp(usersPlugin);
src/app.js — یکپارچه کردن
const fastify = require('fastify')({ logger: true }); // register — اضافه کردن plugin با prefix fastify.register(require('./plugins/users'), { prefix: '/api/v1' }); fastify.register(require('./plugins/orders'), { prefix: '/api/v1' }); // پکیج‌های آماده Fastify fastify.register(require('@fastify/cors'), { origin: ['http://localhost:3000', 'https://myapp.com'] }); fastify.register(require('@fastify/helmet')); // security headers fastify.register(require('@fastify/jwt'), { secret: process.env.JWT_SECRET }); // Health check // GET /health → سرور زنده است؟ fastify.get('/health', async () => ({ status: 'ok', timestamp: new Date().toISOString() })); module.exports = fastify;

نکات کلیدی برای مصاحبه

  • Fastify از JSON Schema برای validation استفاده می‌کند — سریع‌تر از validation دستی.
  • response schema مثل یک whitelist است — فقط فیلدهای تعریف‌شده برمی‌گردند. password را از response خارج کنید!
  • Hooks برای cross-cutting concerns مثل auth، logging، rate limiting.
  • HTTP status codeها: 200 OK، 201 Created، 204 No Content، 400 Bad Request، 401 Unauthorized، 403 Forbidden، 404 Not Found، 500 Internal Error.
  • Plugin system برای modular کردن کد — هر domain (users، orders، products) یک plugin جداگانه.
  • در Fastify هر async function خودکار خطاها را catch می‌کند — نیاز به try/catch در route handler نیست.
  • سوال رایج: «فرق 401 و 403 چیست؟» — 401 یعنی «شما احراز هویت نشده‌اید» (لاگین نکرده‌اید)؛ 403 یعنی «احراز هویت شده‌اید ولی اجازه این کار را ندارید».
  • یک تله رایج: برگرداندن 200 برای همه چیز، حتی خطاها — کلاینت نمی‌تواند به‌راحتی تشخیص دهد موفق بوده یا نه؛ همیشه status code مناسب استفاده کنید.
  • Idempotent methods در REST: GET، PUT، DELETE اگر چند بار با هم پارامتر تکرار شوند نتیجه یکسان دارند؛ POST معمولاً idempotent نیست (هر بار یک منبع جدید می‌سازد).
  • Fastify نسبت به Express سریع‌تر است چون از JSON Schema برای serialize کردن پاسخ هم استفاده می‌کند — این کار را در C++ level انجام می‌دهد، نه با JSON.stringify معمولی.
