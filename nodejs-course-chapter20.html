MongoDB
دیتابیس NoSQL

MongoDB یک دیتابیس NoSQL است که داده‌ها را به صورت document (شبیه JSON) ذخیره می‌کند. در این فصل با Mongoose — محبوب‌ترین ODM برای MongoDB — یاد می‌گیریم چطور schema تعریف کنیم، query بنویسیم و روابط بین document‌ها را مدیریت کنیم.

MongoDB Mongoose Schema CRUD Aggregation Populate

SQL vs MongoDB — چه فرقی دارند؟

قبل از یادگیری MongoDB باید تفاوتش با دیتابیس‌های رابطه‌ای (مثل MySQL) را بدانید:

SQL (مثل MySQL)

داده در جداول با ردیف و ستون

Schema ثابت — همه ردیف‌ها یک شکل

JOIN برای روابط

مناسب: داده‌های ساختارمند، transaction مهم

MongoDB (NoSQL)

داده در document — شبیه JSON

Schema انعطاف‌پذیر — هر document می‌تواند فرق داشته باشد

Embed یا Reference برای روابط

مناسب: داده‌های متغیر، scaling افقی

اصطلاحات معادل: جدول (Table) → Collection | ردیف (Row) → Document | ستون (Column) → Field | JOIN → Populate

terminal
npm install mongoose

const mongoose = require('mongoose'); async function connectDB() { try { const conn = await mongoose.connect(process.env.DB_URL, { // این optionها دیگر لازم نیستند در Mongoose 6+ ولی می‌بینیدشان }); console.log(`✅ MongoDB متصل شد: ${conn.connection.host}`); } catch (error) { console.error('❌ خطا در اتصال MongoDB:', error.message); process.exit(1); } } // رویدادهای connection mongoose.connection.on('disconnected', () => { console.warn('MongoDB قطع شد'); }); module.exports = connectDB;

Schema و Model تعریف کنید

در Mongoose ابتدا Schema تعریف می‌کنید — شکل document را مشخص می‌کند. سپس از Schema یک Model می‌سازید — interface اصلی برای کار با دیتابیس است.

models/User.js
const mongoose = require('mongoose'); const userSchema = new mongoose.Schema({ name: { type: String, required: [true, 'نام الزامی است'], trim: true, minlength: 2, maxlength: 50 }, email: { type: String, required: true, unique: true, // unique index می‌سازد lowercase: true, // خودکار lowercase می‌کند match: [/\S+@\S+\.\S+/, 'ایمیل نامعتبر است'] }, password: { type: String, required: true, select: false // در query‌ها خودکار حذف می‌شود }, role: { type: String, enum: ['user', 'admin'], default: 'user' }, age: { type: Number, min: 0, max: 120 }, isActive: { type: Boolean, default: true }, tags: [String], // آرایه از string address: { city: String, country: { type: String, default: 'Iran' } } }, { timestamps: true // خودکار createdAt و updatedAt اضافه می‌کند }); // Virtual — field محاسبه‌شده که در DB ذخیره نمی‌شود userSchema.virtual('displayName').get(function() { return `${this.name} (${this.role})`; }); // Middleware — قبل از save اجرا می‌شود userSchema.pre('save', async function(next) { // اگر password تغییر کرده، hash کنید if (this.isModified('password')) { this.password = await bcrypt.hash(this.password, 12); } next(); }); const User = mongoose.model('User', userSchema); // 'User' → در MongoDB collection به نام 'users' می‌شود (plural lowercase) module.exports = User;

CRUD Operations با Mongoose

services/userService.js — CRUD کامل
const User = require('../models/User'); // CREATE — ساخت document جدید async function createUser(data) { const user = await User.create(data); // یا: const user = new User(data); await user.save(); return user; } // READ — خواندن async function getUsers({ page = 1, limit = 10, role }) { const filter = role ? { role } : {}; const [users, total] = await Promise.all([ User.find(filter) .select('-password') // password را حذف کن .sort({ createdAt: -1 }) // جدیدترین اول .skip((page - 1) * limit) // pagination .limit(limit) .lean(), // plain JS object — سریع‌تر User.countDocuments(filter) ]); return { users, total, pages: Math.ceil(total / limit) }; } async function getUserById(id) { return User.findById(id).select('-password').lean(); } // UPDATE — آپدیت async function updateUser(id, data) { return User.findByIdAndUpdate( id, { $set: data }, // فقط فیلدهای داده شده آپدیت شود { new: true, runValidators: true } // new: document آپدیت شده برگردد // runValidators: schema validation اجرا شود ); } // DELETE — حذف async function deleteUser(id) { return User.findByIdAndDelete(id); } module.exports = { createUser, getUsers, getUserById, updateUser, deleteUser };

Query Operators — فیلترهای پیشرفته

query-operators.js
// مقایسه User.find({ age: { $gt: 18 } }); // age > 18 User.find({ age: { $gte: 18, $lte: 65 } }); // 18 <= age <= 65 User.find({ role: { $in: ['admin', 'moderator'] } }); // یکی از این‌ها User.find({ role: { $ne: 'banned'} }); // not equal // منطقی User.find({ $and: [{ isActive: true }, { age: { $gt: 18 } }] }); User.find({ $or: [{ role: 'admin' }, { role: 'moderator' }] }); // متن — جستجو در رشته User.find({ name: /ali/i }); // regex — case insensitive User.find({ $text: { $search: 'ali' } }); // text index لازم دارد // آرایه User.find({ tags: 'nodejs' }); // آرایه شامل این مقدار User.find({ tags: { $all: ['nodejs', 'js'] } }); // همه این‌ها // Update operators User.updateOne({ _id: id }, { $set: { name: 'Ali' }, // مقدار را set کن $inc: { loginCount: 1 }, // عدد را اضافه کن $push: { tags: 'nodejs' }, // به آرایه اضافه کن $pull: { tags: 'php' }, // از آرایه حذف کن $unset: { temporaryField: '' } // field را حذف کن });

Populate — روابط بین Collection‌ها

وقتی یک document به document دیگری reference دارد، با populate می‌توانید آن را لود کنید — مثل JOIN در SQL:

models/Post.js و populate
// Post با reference به User const postSchema = new mongoose.Schema({ title: String, body: String, author: { type: mongoose.Schema.Types.ObjectId, ref: 'User' // به model 'User' اشاره دارد }, tags: [String] }, { timestamps: true }); const Post = mongoose.model('Post', postSchema); // Populate — جزئیات author را لود کن const posts = await Post .find({ tags: 'nodejs' }) .populate('author', 'name email') // فقط name و email .sort({ createdAt: -1 }) .lean(); // نتیجه: // { title: '...', author: { name: 'Ali', email: 'ali@test.com' }, ... }

نکات کلیدی برای مصاحبه

  • MongoDB داده را به صورت BSON (Binary JSON) ذخیره می‌کند — از اینجاست که شبیه JSON به نظر می‌رسد.
  • Mongoose Schema ساختار document را تعریف می‌کند و validation را handle می‌کند.
  • lean() را هر وقت نیازی به Mongoose document methods ندارید استفاده کنید — سریع‌تر است.
  • از $set در update استفاده کنید — بدون آن، کل document جایگزین می‌شود.
  • Index بسازید روی field‌هایی که زیاد query می‌شوند: userSchema.index({ email: 1 })
  • Populate مثل JOIN است ولی چند query به DB می‌زند — برای داده‌های کم مناسب است.
  • سوال رایج: «MongoDB چه زمانی مناسب‌تر از SQL است؟» — وقتی ساختار داده متغیر است یا nested پیچیده دارد (مثل یک پست با کامنت‌های تودرتو)؛ برای داده‌های رابطه‌ای سنگین با نیاز به transaction دقیق، SQL معمولاً بهتر است.
  • یک تله رایج: استفاده نکردن از index و بعد شکایت از کندی query روی جدول بزرگ — بدون index، MongoDB باید همه document‌ها را یکی‌یکی بررسی کند (collection scan).
  • Embedding vs Referencing: داده‌ای که همیشه با هم خوانده می‌شود را embed کنید (مثل آدرس در user)؛ داده‌ای که مستقل رشد می‌کند یا در جاهای مختلف استفاده می‌شود را reference کنید (مثل پست‌های یک کاربر).
  • عملیات Aggregation Pipeline برای query‌های پیچیده (گروه‌بندی، محاسبه، join چندمرحله‌ای) استفاده می‌شود — قوی‌تر از find ساده است.
