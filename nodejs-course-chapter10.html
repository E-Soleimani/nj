Object Oriented
Programming

برنامه‌نویسی شی‌گرا یک روش سازماندهی کد است که بر اساس «اشیاء» کار می‌کند. در Node.js از OOP برای ساختن layerهای Service، Repository و Model استفاده می‌شود. این فصل مفاهیم کلاس، وراثت و polymorphism را با مثال‌های واقعی یاد می‌دهد.

چهار اصل OOP

قبل از کد، باید این چهار مفهوم را بفهمید:

🔒

Encapsulation — کپسوله‌سازی

پنهان کردن جزئیات داخلی. فقط از طریق متدهای عمومی می‌توان به داده دسترسی داشت. مثل یک ماشین — موتور را نمی‌بینید ولی با پدال کار می‌کنید.

🧬

Inheritance — وراثت

یک class می‌تواند ویژگی‌های class دیگری را به ارث ببرد و گسترش دهد. کد تکراری نمی‌نویسیم.

🎭

Polymorphism — چندریختی

اشیاء مختلف می‌توانند به یک دستور به روش‌های متفاوت پاسخ دهند. مثل send() که برای email، SMS و push متفاوت کار می‌کند.

🎯

Abstraction — انتزاع

پیچیدگی را پنهان کنید. کاربر فقط با interface کار می‌کند، نه جزئیات پیاده‌سازی.

Class در JavaScript

Class یک قالب (template) برای ساخت object است. با keyword new از یک class، یک instance می‌سازید. هر instance داده‌های خودش را دارد ولی متدها را با هم share می‌کنند.

class-basics.js
class BankAccount { // Private fields — # یعنی فقط داخل class قابل دسترس #balance; #owner; #transactions; // constructor — وقتی new BankAccount() صدا زده می‌شود اجرا می‌شود constructor(owner, initialBalance = 0) { this.#owner = owner; this.#balance = initialBalance; this.#transactions = []; } // Getter — مثل property ولی با منطق get balance() { return this.#balance; } get owner() { return this.#owner; } // متدهای عمومی — interface برای کار با account deposit(amount) { if (amount <= 0) throw new Error('Amount must be positive'); this.#balance += amount; this.#transactions.push({ type: 'deposit', amount, date: new Date() }); return this; // برای method chaining } withdraw(amount) { if (amount > this.#balance) throw new Error('Insufficient funds'); this.#balance -= amount; this.#transactions.push({ type: 'withdrawal', amount, date: new Date() }); return this; } getStatement() { return { owner: this.#owner, balance: this.#balance, transactions: [...this.#transactions] }; } // Static method — بدون new اجرا می‌شود static validateIBAN(iban) { return iban.startsWith('IR') && iban.length === 26; } } // ساخت instance const account = new BankAccount('Ali', 1000000); // method chaining account.deposit(500000).withdraw(200000); console.log(account.balance); // 1300000 // account.#balance ← SyntaxError! private است // static بدون new console.log(BankAccount.validateIBAN('IR123456789012345678901234')); // true

Inheritance — وراثت با extends

با extends یک class می‌تواند همه ویژگی‌های class دیگر را به ارث ببرد و چیزهای جدیدی اضافه کند یا رفتارها را تغییر دهد.

inheritance.js
// class پایه — اطلاعات مشترک همه کاربران class User { constructor(name, email) { this.name = name; this.email = email; this.createdAt = new Date(); this.isActive = true; } greet() { return `سلام، من ${this.name} هستم`; } deactivate() { this.isActive = false; } } // AdminUser از User ارث می‌برد class AdminUser extends User { constructor(name, email, permissions) { // super() باید اول صدا زده شود — constructor والد را اجرا می‌کند super(name, email); this.permissions = permissions; this.role = 'admin'; } // Override — تغییر رفتار متد والد greet() { // super.greet() متد والد را صدا می‌زند return `${super.greet()} [ادمین]`; } // متد جدید — فقط AdminUser این را دارد hasPermission(perm) { return this.permissions.includes(perm); } grantPermission(perm) { if (!this.hasPermission(perm)) { this.permissions.push(perm); } } } const admin = new AdminUser('Elshan', 'e@example.com', ['read', 'write']); console.log(admin.greet()); // سلام، من Elshan هستم [ادمین] console.log(admin.hasPermission('delete')); // false admin.grantPermission('delete'); console.log(admin.hasPermission('delete')); // true // instanceof — چک می‌کند آیا از یک class است console.log(admin instanceof AdminUser); // true console.log(admin instanceof User); // true — چون AdminUser از User ارث برده

Polymorphism — یک interface، چند رفتار

Polymorphism یعنی می‌توانید با اشیاء مختلف به یک روش کار کنید، و هر کدام به روش خودشان پاسخ می‌دهند. این کد را قابل گسترش می‌کند.

polymorphism.js
// class پایه با interface مشترک class Notification { send(message, recipient) { throw new Error('متد send باید implement شود'); } } // هر زیرکلاس به روش خودش send می‌کند class EmailNotification extends Notification { send(message, recipient) { // کد ارسال ایمیل اینجا console.log(`📧 Email به ${recipient}: ${message}`); } } class SMSNotification extends Notification { send(message, recipient) { // کد ارسال SMS اینجا console.log(`📱 SMS به ${recipient}: ${message}`); } } class PushNotification extends Notification { send(message, recipient) { console.log(`🔔 Push به ${recipient}: ${message}`); } } // قدرت polymorphism — همه با یک روش استفاده می‌شوند function notifyUser(notifier, message, user) { // نمی‌دانیم چه نوع notifier است — فقط می‌دانیم send() دارد notifier.send(message, user); } const notifiers = [ new EmailNotification(), new SMSNotification(), new PushNotification(), ]; // همه به یک روش صدا زده می‌شوند notifiers.forEach(n => notifyUser(n, 'سفارش شما ثبت شد', 'ali@test.com')); // 📧 Email به ali@test.com: سفارش شما ثبت شد // 📱 SMS به ali@test.com: سفارش شما ثبت شد // 🔔 Push به ali@test.com: سفارش شما ثبت شد

الگوی واقعی در Node.js — Service و Repository

در Node.js معمولاً کد را در لایه‌ها سازماندهی می‌کنیم. Repository مسئول ارتباط با database است. Service منطق اصلی (business logic) را دارد. این separation باعث می‌شود تست‌نویسی و تغییر راحت‌تر باشد:

repository-service-pattern.js
// Base Repository — interface مشترک برای همه repositoryها class BaseRepository { async findById(id) { throw new Error('Not implemented'); } async findAll() { throw new Error('Not implemented'); } async create(data) { throw new Error('Not implemented'); } async update(id, data){ throw new Error('Not implemented'); } async delete(id) { throw new Error('Not implemented'); } } // پیاده‌سازی با MongoDB class UserRepository extends BaseRepository { constructor(UserModel) { super(); this.model = UserModel; } async findById(id) { return this.model.findById(id).lean(); } async findByEmail(email) { return this.model.findOne({ email }).lean(); } async create(data) { const user = new this.model(data); return user.save(); } } // Service — منطق اصلی، از Repository استفاده می‌کند class UserService { constructor(userRepository) { this.repo = userRepository; } async getUserById(id) { const user = await this.repo.findById(id); if (!user) throw new Error('User not found'); // منطق اضافه — مثلاً password را حذف کنید const { password, ...safeUser } = user; return safeUser; } async registerUser(name, email, password) { // چک کنید ایمیل تکراری نباشد const existing = await this.repo.findByEmail(email); if (existing) throw new Error('Email already exists'); // hash کردن password و ذخیره return this.repo.create({ name, email, password }); } }

نکات کلیدی برای مصاحبه

  • از #privateField برای private properties استفاده کنید — نه underscore (_name) که فقط convention است و واقعاً private نیست.
  • در constructor فرزند، همیشه اول super() صدا بزنید — بدون آن Error می‌گیرید.
  • instanceof با inheritance کار می‌کند: AdminUser instanceof User = true.
  • Static methods روی class فراخوانی می‌شوند نه روی instance: BankAccount.validate().
  • در Node.js OOP بیشتر در لایه‌های Service، Repository و Model استفاده می‌شود.
  • JavaScript از Prototype-based inheritance استفاده می‌کند — class فقط syntax sugar است، نه OOP واقعی مثل Java.
  • چهار اصل OOP: Encapsulation (پنهان کردن جزئیات داخلی)، Inheritance (ارث‌بری رفتار)، Polymorphism (رفتار متفاوت با یک اسم متد)، Abstraction (پنهان کردن پیچیدگی پشت یک interface ساده).
  • سوال رایج: «فرق composition و inheritance چیست؟» — inheritance یعنی «است» (Dog یک Animal است)؛ composition یعنی «دارد» (Car یک Engine دارد). composition معمولاً انعطاف بیشتری می‌دهد و کمتر به مشکل «هرم وراثت پیچیده» می‌خورد.
  • یک تله رایج: زیاد استفاده کردن از inheritance عمیق (چند لایه extends) — نگهداری‌اش سخت می‌شود؛ اصل معروف: «Composition over Inheritance».
  • در JavaScript، متدهای یک class روی prototype ذخیره می‌شوند، نه روی هر instance جداگانه — یعنی همه instanceها یک نسخه از متد را به اشتراک می‌گذارند و حافظه کمتری مصرف می‌شود.
