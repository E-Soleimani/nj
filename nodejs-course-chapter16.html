Async Flow
Control

کنترل جریان کدهای async — چطور چند کار async را به ترتیب یا موازی اجرا کنیم، آن‌ها را cancel کنیم، timeout بگذاریم، یا retry کنیم. این الگوها در پروژه‌های واقعی خیلی رایج هستند.

Sequential Parallel Retry Timeout AbortController Queue

چهار الگوی اصلی Flow Control

Sequential — ترتیبی

کارها یکی یکی اجرا می‌شوند. هر کار منتظر تمام شدن قبلی است. وقتی کارها به هم وابسته‌اند.

Parallel — موازی

همه کارها همزمان شروع می‌شوند. وقتی کارها مستقل از هم هستند و می‌خواهیم سریع‌تر تمام شوند.

Race — مسابقه

همه شروع می‌شوند ولی فقط اولین نتیجه استفاده می‌شود. برای timeout و fallback.

Throttle/Queue — صف

محدود کردن تعداد کارهای همزمان. وقتی API خارجی rate limit دارد.

Sequential — اجرای ترتیبی

وقتی نتیجه هر کار برای کار بعدی لازم است، باید ترتیبی اجرا کنید. ساده‌ترین حالت با await است:

sequential.js
// ساده‌ترین حالت — await یکی یکی async function processOrder(orderId) { // مرحله ۱: گرفتن سفارش const order = await db.getOrder(orderId); // مرحله ۲: چک کردن موجودی — به order نیاز دارد const inStock = await inventory.check(order.items); if (!inStock) throw new Error('موجودی کافی نیست'); // مرحله ۳: پردازش پرداخت — به order نیاز دارد const payment = await paymentService.charge(order.total); // مرحله ۴: ارسال — به payment نیاز دارد await shippingService.dispatch(order, payment.transactionId); return { order, payment, status: 'shipped' }; } // اجرای sequential روی آرایه — for...of async function processAllOrders(orderIds) { const results = []; // forEach با async کار نمی‌کند! از for...of استفاده کنید for (const id of orderIds) { const result = await processOrder(id); results.push(result); console.log(`سفارش ${id} پردازش شد`); } return results; } // reduce برای sequential — الگوی جالب async function sequentialReduce(tasks) { return tasks.reduce( async (prevPromise, task) => { const prev = await prevPromise; // منتظر قبلی const result = await task(); return [...prev, result]; }, Promise.resolve([]) ); }

Timeout — محدود کردن زمان انتظار

گاهی یک کار async خیلی طول می‌کشد — مثلاً API خارجی جواب نمی‌دهد. باید بعد از مدت مشخصی timeout بدهیم و خطا برگردانیم:

timeout-pattern.js
// تابع کمکی — timeout را به یک Promise اضافه می‌کند function withTimeout(promise, ms, message = 'Operation timed out') { let timeoutId; const timeoutPromise = new Promise((_, reject) => { timeoutId = setTimeout(() => { reject(new Error(message)); }, ms); }); return Promise.race([promise, timeoutPromise]) .finally(() => clearTimeout(timeoutId)); // timeout را پاک کن } // استفاده async function callExternalAPI() { try { const result = await withTimeout( fetch('https://api.example.com/data'), 5000, // 5 ثانیه 'API در ۵ ثانیه جواب نداد' ); return result.json(); } catch (error) { console.error('API call failed:', error.message); throw error; } } // Node.js v18+ — AbortController برای cancel کردن fetch async function fetchWithAbort(url, timeoutMs) { const controller = new AbortController(); const timeoutId = setTimeout(() => { controller.abort(); // درخواست را cancel کن }, timeoutMs); try { const response = await fetch(url, { signal: controller.signal // AbortSignal را به fetch می‌دهیم }); return response.json(); } catch (error) { if (error.name === 'AbortError') { throw new Error(`Request to ${url} timed out`); } throw error; } finally { clearTimeout(timeoutId); } }

Retry — تلاش مجدد

گاهی یک کار async به دلیل مشکل موقت شبکه fail می‌شود. به جای دادن خطا، چند بار دوباره امتحان می‌کنیم:

retry-pattern.js
// تابع retry با exponential backoff async function retry(fn, options = {}) { const { attempts = 3, // تعداد تلاش delay = 1000, // تاخیر اولیه (ms) backoff = 2, // ضریب افزایش تاخیر shouldRetry = () => true // کدام خطاها را retry کنیم } = options; let lastError; for (let attempt = 1; attempt <= attempts; attempt++) { try { return await fn(); // اگر موفق شد، نتیجه برگردان } catch (error) { lastError = error; if (attempt === attempts || !shouldRetry(error)) { break; // آخرین تلاش یا خطای قابل retry نیست } const waitTime = delay * Math.pow(backoff, attempt - 1); console.log(`تلاش ${attempt} ناموفق. ${waitTime}ms صبر می‌کنیم...`); await new Promise(resolve => setTimeout(resolve, waitTime)); } } throw lastError; } // استفاده async function main() { try { const data = await retry( () => fetch('https://api.example.com/data'), { attempts: 3, delay: 1000, backoff: 2, // فقط خطاهای شبکه را retry کن، خطاهای 400 را نه shouldRetry: (err) => err.name !== 'ValidationError' } ); // تلاش ۱: بلافاصله // تلاش ۲: بعد از 1 ثانیه // تلاش ۳: بعد از 2 ثانیه } catch (err) { console.error('بعد از همه تلاش‌ها ناموفق:', err.message); } }

Concurrency Control — محدود کردن همزمانی

فرض کنید ۱۰۰۰ تصویر باید پردازش شوند. اگر همه را همزمان شروع کنیم، حافظه و CPU اشباع می‌شوند. باید تعداد کارهای همزمان را محدود کنیم:

concurrency-limit.js
// اجرای حداکثر n کار همزمان async function runWithConcurrency(tasks, limit) { const results = []; const executing = new Set(); for (const task of tasks) { // یک Promise می‌سازیم و به Set اضافه می‌کنیم const p = task().then(result => { executing.delete(p); return result; }); results.push(p); executing.add(p); // اگر به limit رسیدیم، منتظر یکی تمام شود if (executing.size >= limit) { await Promise.race(executing); } } return Promise.all(results); } // استفاده — پردازش 100 تصویر، حداکثر 5 تا همزمان const imageIds = Array.from({ length: 100 }, (_, i) => i + 1); const tasks = imageIds.map(id => () => processImage(id)); const results = await runWithConcurrency(tasks, 5); console.log(`${results.length} تصویر پردازش شد`);

EventEmitter — الگوی رویداد

EventEmitter یکی از مهم‌ترین ابزارهای Node.js است. به جای callback مستقیم، رویداد emit می‌کنید و listener‌ها آن را دریافت می‌کنند. این الگو در خود Node.js (fs، http، stream) و در پکیج‌هایی مثل Socket.io زیاد استفاده می‌شود:

event-emitter.js
const { EventEmitter } = require('events'); // ساختن یک EventEmitter class OrderProcessor extends EventEmitter { async process(order) { this.emit('started', { orderId: order.id }); try { await paymentService.charge(order.total); this.emit('payment_done', { orderId: order.id }); await shippingService.dispatch(order); this.emit('completed', { orderId: order.id }); } catch (error) { this.emit('error', { orderId: order.id, error }); } } } // استفاده const processor = new OrderProcessor(); // subscribe به رویدادها processor.on('started', ({ orderId }) => console.log(`شروع: ${orderId}`)); processor.on('payment_done', ({ orderId }) => console.log(`پرداخت: ${orderId}`)); processor.on('completed', ({ orderId }) => console.log(`تمام: ${orderId}`)); processor.on('error', ({ orderId, error }) => console.error(`خطا در ${orderId}: ${error.message}`) ); // once — فقط یک بار اجرا می‌شود processor.once('completed', () => console.log('اولین سفارش تمام شد!')); await processor.process({ id: 'ORDER-001', total: 50000 });

نکات کلیدی برای مصاحبه

  • برای اجرای آرایه‌ای از async tasks به صورت sequential از for...of استفاده کنید — نه forEach.
  • Promise.all موازی اجرا می‌کند. await در حلقه ترتیبی اجرا می‌کند — تفاوت مهم است.
  • AbortController برای cancel کردن fetch یا هر کار async که signal را قبول می‌کند.
  • الگوی Retry با exponential backoff: بعد از هر fail، مدت انتظار را دو برابر کنید.
  • EventEmitter برای decoupling — فرستنده رویداد نمی‌داند چه کسی گوش می‌دهد.
  • Concurrency control برای جلوگیری از overload — هیچ‌وقت هزار کار را همزمان شروع نکنید.
  • سوال رایج: «چطور یک درخواست fetch را بعد از ۵ ثانیه لغو کنیم؟» — با AbortController یک signal بسازید، به fetch بدهید، و با setTimeout بعد از ۵ ثانیه controller.abort() را صدا بزنید.
  • یک تله رایج: در exponential backoff فراموش کردن سقف تعداد retry — بدون محدودیت، ممکن است یک سرویس خراب برای همیشه retry شود و منابع را اشغال کند.
  • Debounce یعنی صبر کردن تا فعالیت متوقف شود، بعد اجرا (مثل جستجو موقع تایپ)؛ Throttle یعنی حداکثر یک بار در بازه زمانی مشخص اجرا شود، فارغ از تعداد فراخوانی.
  • ترکیب Promise.all با map برای اجرای موازی روی آرایه رایج است: await Promise.all(items.map(fetchOne)) — اما اگر یکی fail شود، همه fail می‌شوند؛ برای مقاومت بیشتر از Promise.allSettled استفاده کنید.
