Node.js چیست؟

Node.js یک محیط اجرای JavaScript است — یعنی به شما اجازه می‌دهد کد JavaScript را خارج از مرورگر، مستقیماً روی سیستم‌عامل اجرا کنید. قبل از Node.js، JavaScript فقط در مرورگر کار می‌کرد.

مثلاً با Node.js می‌توانید فایل بخوانید، به دیتابیس متصل شوید، یک وب‌سرور بسازید — همه چیزهایی که قبلاً فقط با زبان‌هایی مثل PHP یا Python ممکن بود.

تشبیه ساده: JavaScript مثل یک راننده است. مرورگر مثل یک ماشین بود — راننده فقط با آن ماشین می‌توانست کار کند. Node.js مثل یک کارخانه شد — همان راننده حالا می‌تواند هر ماشینی را برانَد، داخل کارخانه کار کند، سرویس بدهد.

تاریخچه Node.js

Ryan Dahl در سال ۲۰۰۹ Node.js را ساخت. مشکلی که داشت این بود: سرورهای آن زمان (مثل Apache) برای هر درخواست یک thread جدید می‌ساختند. هر thread حافظه مصرف می‌کند. وقتی ۱۰۰۰۰ کاربر همزمان وارد سایت شوند، سرور ۱۰۰۰۰ thread داشت — این خیلی سنگین بود. Ryan می‌خواست با یک thread هزاران درخواست مدیریت کند.

2009

تولد Node.js

Ryan Dahl در JSConf EU اولین نسخه را معرفی کرد. موتور V8 گوگل به عنوان پایه انتخاب شد چون سریع‌ترین JavaScript engine آن زمان بود.

2010

NPM متولد شد

Isaac Schlueter پکیج منیجر npm را ساخت. برنامه‌نویسان می‌توانستند کدشان را به اشتراک بگذارند. اکوسیستم شروع به رشد انفجاری کرد.

2015

بنیاد Node.js

بعد از یک fork به نام io.js، دو تیم دوباره متحد شدند و Node.js Foundation تشکیل شد. نسخه‌های پایدار LTS معرفی شدند.

2018

Worker Threads

برای اولین بار multi-threading واقعی اضافه شد — برای کارهای سنگین CPU مثل پردازش تصویر.

2024

Node.js v22 LTS

امروز Node.js در Netflix، LinkedIn، Uber، PayPal و میلیون‌ها پروژه دیگر استفاده می‌شود.

معماری Node.js — چهار لایه اصلی

Node.js از چند لایه تشکیل شده. هر لایه کار خاصی دارد:

🚀

V8 Engine

موتور JavaScript که گوگل برای Chrome ساخته. کد JS را مستقیم به machine code تبدیل می‌کند — بدون مرحله میانی. به همین دلیل Node.js خیلی سریع است.

⚙️

libuv

یک کتابخانه C که Event Loop و عملیات async I/O را مدیریت می‌کند. وقتی فایل می‌خوانید یا به شبکه وصل می‌شوید، libuv این کار را انجام می‌دهد — نه V8.

📦

Node.js Core APIs

ماژول‌های built-in مثل fs (فایل)، http (وب)، path (مسیر)، crypto (رمزنگاری). به C++ نوشته شده‌اند و از طریق JavaScript قابل استفاده‌اند.

🌐

npm Ecosystem

بیش از ۲ میلیون پکیج آماده. هر کاری که بخواهید انجام دهید، احتمالاً کسی قبلاً یک پکیج برایش نوشته.

Event Loop — قلب Node.js

مهم‌ترین مفهوم در Node.js Event Loop است. اما قبل از آن باید بدانید تفاوت Blocking و Non-blocking چیست.

Blocking چیست؟

وقتی کدی blocking است، یعنی تا آن کار تمام نشود، هیچ کار دیگری نمی‌تواند انجام شود. مثل یک صف بانک که تا نفر جلویی کارش تمام نشود، نوبت بعدی نمی‌رسد.

Non-blocking چیست؟

Node.js به جای منتظر ماندن، کار را شروع می‌کند و می‌رود سراغ کار بعدی. وقتی کار اول تمام شد، Node.js خبردار می‌شود و نتیجه را پردازش می‌کند. این همان چیزی است که Event Loop انجام می‌دهد.

تشبیه Event Loop: تصور کنید یک آشپز دارید. اگر آشپز blocking باشد، جلوی اجاق می‌ایستد و منتظر می‌ماند آب قل بیاید — هیچ کار دیگری نمی‌کند. Node.js مثل یک آشپز هوشمند است: آب را روی گاز می‌گذارد، می‌رود سبزی خرد می‌کند، وقتی آب جوشید برمی‌گردد. با یک آشپز (thread) ده تا کار موازی انجام می‌دهد.

blocking-vs-nonblocking.js
// ❌ روش Blocking — تا فایل خوانده نشود، هیچ چیز اجرا نمی‌شود const fs = require('fs'); const data = fs.readFileSync('bigfile.txt', 'utf8'); console.log(data); // این خط منتظر می‌ماند — اگر فایل 5 ثانیه طول بکشد، // هیچ درخواست دیگری در این 5 ثانیه پاسخ نمی‌گیرد! console.log('بعد از فایل'); // ✅ روش Non-blocking — Node.js منتظر نمی‌ماند fs.readFile('bigfile.txt', 'utf8', (err, data) => { // این callback وقتی فایل آماده شد صدا زده می‌شود if (err) throw err; console.log(data); }); // این خط بلافاصله اجرا می‌شود — منتظر فایل نمی‌ماند! console.log('این قبل از خواندن فایل چاپ می‌شود'); // خروجی: // این قبل از خواندن فایل چاپ می‌شود // [محتوای فایل — وقتی آماده شد]

Event Loop چطور کار می‌کند؟

Event Loop یک حلقه بی‌نهایت است که مدام چک می‌کند: «آیا کاری هست که باید انجام شود؟» Node.js کارها را در صف می‌گذارد. Event Loop یکی یکی از صف برمی‌دارد و اجرا می‌کند. اگر کاری async است (مثل خواندن فایل)، آن را به سیستم‌عامل می‌دهد و خودش به کار بعدی می‌رود.

event-loop-order.js
// این مثال ترتیب دقیق اجرا را نشان می‌دهد console.log('۱ — همزمان (synchronous)'); setTimeout(() => { console.log('۴ — setTimeout (macrotask)'); }, 0); // حتی با 0ms تاخیر، بعد از Promise‌ها اجرا می‌شود Promise.resolve().then(() => { console.log('۳ — Promise (microtask)'); }); // Promiseها در صف microtask هستند — قبل از setTimeout console.log('۲ — همزمان (synchronous)'); // خروجی واقعی: // ۱ — همزمان // ۲ — همزمان // ۳ — Promise (microtask) // ۴ — setTimeout (macrotask)
💡

چرا این مهم است؟ وقتی باگ عجیبی دارید که ترتیب اجرا اشتباه است، دانستن Event Loop کمک می‌کند سریع مشکل را پیدا کنید. این یکی از سوالات رایج مصاحبه است.

اولین برنامه Node.js — سرور HTTP

ماژول http یکی از built-in ماژول‌های Node.js است. با آن می‌توانید یک وب‌سرور بسازید — بدون هیچ پکیج خارجی. این مثال نشان می‌دهد Node.js چقدر ساده است:

server.js
// require — ماژول http را وارد می‌کنیم (built-in است، نیازی به npm install نیست) const http = require('http'); // createServer — یک سرور می‌سازیم // هر بار که درخواستی بیاید، این callback اجرا می‌شود // req = اطلاعات درخواست (URL، method، headers) // res = پاسخی که باید بفرستیم const server = http.createServer((req, res) => { // writeHead — status code و headers را تنظیم می‌کنیم // 200 = موفق، Content-Type می‌گوید پاسخ چه نوعی است res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' }); // end — پاسخ را می‌فرستیم و connection را می‌بندیم res.end('سلام دنیا! Node.js کار می‌کند 🎉'); }); // listen — سرور را روی پورت 3000 شروع می‌کنیم // callback وقتی سرور آماده شد اجرا می‌شود server.listen(3000, () => { console.log('✅ سرور روی http://localhost:3000 آماده است'); }); // اجرا: node server.js // بعد مرورگر: http://localhost:3000

Node.js کجا خوب نیست؟ برای محاسبات سنگین CPU (مثل پردازش تصویر، رمزگشایی، یادگیری ماشین) مناسب نیست — چون تنها thread را block می‌کند و همه درخواست‌ها صبر می‌کنند. برای این کارها از Worker Threads یا زبان‌های دیگر استفاده کنید.

نکات کلیدی برای مصاحبه

  • Node.js یک runtime است، نه یک زبان. زبان همان JavaScript است، فقط محیط اجرا فرق کرده.
  • V8 کد JS را اجرا می‌کند — همان موتور Chrome، ساخت گوگل.
  • libuv کتابخانه‌ای است که Event Loop و کارهای async را مدیریت می‌کند.
  • Node.js تک‌ترد است ولی با Event Loop هزاران request را همزمان جواب می‌دهد.
  • Non-blocking یعنی منتظر نمی‌ماند؛ کار را می‌فرستد و می‌رود سراغ بعدی.
  • سازنده Node.js، Ryan Dahl، بعدها Deno را هم ساخت.
  • یک سوال رایج: «اگه Node تک‌رشته‌ایه، چطور چند کار را همزمان انجام می‌دهد؟» — جواب کوتاه: جاوااسکریپت تک‌رشته اجرا می‌شود، ولی libuv کارهای سنگین (فایل، شبکه) را به Thread Pool سیستم می‌سپارد.
  • Node.js برای I/O (فایل، دیتابیس، شبکه) عالی است؛ برای پردازش سنگین CPU (مثل رمزنگاری) مناسب نیست، چون ترد را برای مدت طولانی اشغال می‌کند.
  • فرق با مدل سنتی (مثل PHP): آنجا هر request یک ترد جدید می‌گیرد؛ Node.js با یک ترد و Event Loop، همه را مدیریت می‌کند.
  • یک تله رایج: فکر نکنید Node «هیچ تردی» ندارد — فقط کد شما تک‌ترد اجرا می‌شود؛ در پشت صحنه، libuv از چند ترد سیستم استفاده می‌کند.
