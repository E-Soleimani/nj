فراتر از پایه NestJS

در فصل ۲۳ با ساختار پایه NestJS (Module، Controller، Service، DTO، Guard) آشنا شدیم. استاد گفته این framework تمرکز ویژه مصاحبه است، پس در این فصل عمیق‌تر می‌رویم: Pipes، Interceptors، Exception Filters، Custom Decorators، تست‌نویسی، و ماژول Microservices.

چرخه کامل درخواست در NestJS

هر درخواست HTTP قبل از رسیدن به Controller، از چند لایه عبور می‌کند — ترتیب دقیق آن‌ها مهم است:

request-lifecycle.txt
Request → Middleware (مثل Express — قبل از هر چیز) → Guard (تصمیم: اجازه ورود دارد یا نه) → Interceptor (قبل) (کد قبل از handler) → Pipe (validation و transform ورودی) → Route Handler (منطق اصلی — Controller method) → Interceptor (بعد) (کد بعد از handler، روی response) → Exception Filter (فقط اگر خطا رخ داده باشد) Response

Pipes — Validation و Transformation

Pipe دو کار انجام می‌دهد: داده ورودی را validate می‌کند یا transform (تبدیل نوع) می‌کند — قبل از رسیدن به handler.

Pipe های داخلی NestJS
import { ParseIntPipe, ParseBoolPipe, ParseUUIDPipe, DefaultValuePipe } from '@nestjs/common'; @Controller('products') export class ProductsController { // ParseIntPipe — تبدیل رشته URL به عدد؛ اگر عدد نباشد خودکار 400 می‌دهد @Get(':id') findOne(@Param('id', ParseIntPipe) id: number) { // اینجا id واقعاً از نوع number است، نه string return this.productsService.findOne(id); } // ترکیب چند Pipe و مقدار پیش‌فرض برای query @Get() findAll( @Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number, @Query('inStock', new DefaultValuePipe(true), ParseBoolPipe) inStock: boolean ) { return this.productsService.findAll({ page, inStock }); } }

ساخت یک Custom Pipe

pipes/positive-int.pipe.ts
import { PipeTransform, Injectable, BadRequestException } from '@nestjs/common'; // هر Pipe باید متد transform را implement کند @Injectable() export class PositiveIntPipe implements PipeTransform { transform(value: any) { const num = parseInt(value, 10); if (isNaN(num) || num <= 0) { throw new BadRequestException('باید عدد مثبت باشد'); } return num; } } // استفاده — دقیقاً مثل Pipe های built-in @Get(':quantity') checkStock(@Param('quantity', PositiveIntPipe) quantity: number) { // ... }

ValidationPipe global: در فصل ۲۳ با DTO و class-validator آشنا شدیم. برای اینکه این validation خودکار روی همه route ها اجرا شود، معمولاً یک ValidationPipe سراسری در main.ts ثبت می‌شود: app.useGlobalPipes(new ValidationPipe()).

Interceptors — دور زدن اجرای متد

Interceptor می‌تواند کد را قبل و بعد از اجرای handler اجرا کند — برای logging، تبدیل response، caching، یا اندازه‌گیری زمان اجرا عالی است. بر پایه RxJS Observable ساخته شده (یادآوری فصل ۳۶).

interceptors/logging.interceptor.ts
import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common'; import { Observable } from 'rxjs'; import { tap } from 'rxjs/operators'; @Injectable() export class LoggingInterceptor implements NestInterceptor { intercept(context: ExecutionContext, next: CallHandler): Observable<any> { const request = context.switchToHttp().getRequest(); const start = Date.now(); console.log(`→ ${request.method} ${request.url}`); // قبل از handler // next.handle() اجرای واقعی route handler است return next.handle().pipe( tap(() => { // این بعد از اتمام handler اجرا می‌شود console.log(`← ${request.method} ${request.url} — ${Date.now() - start}ms`); }) ); } } // استفاده روی یک Controller خاص @UseInterceptors(LoggingInterceptor) @Controller('orders') export class OrdersController { /* ... */ }

Interceptor برای تبدیل Response

interceptors/transform.interceptor.ts
import { map } from 'rxjs/operators'; // یک shape استاندارد برای همه response ها (یادآوری فصل 49) @Injectable() export class TransformInterceptor implements NestInterceptor { intercept(context: ExecutionContext, next: CallHandler) { return next.handle().pipe( map(data => ({ success: true, data, timestamp: new Date().toISOString() })) ); // هر چیزی که Controller برگرداند، خودکار در این shape می‌پیچد // Controller فقط return user; می‌نویسد، این Interceptor بقیه را اضافه می‌کند } }

Exception Filters — مدیریت متمرکز خطا

در فصل ۲۳ دیدیم که NotFoundException خودکار به HTTP status تبدیل می‌شود. Exception Filter به شما اجازه می‌دهد این رفتار را سفارشی کنید — مثلاً فرمت خطا را تغییر دهید یا لاگ اضافه کنید.

filters/http-exception.filter.ts
import { ExceptionFilter, Catch, ArgumentsHost, HttpException } from '@nestjs/common'; // @Catch(HttpException) — فقط خطاهایی که HttpException هستند را می‌گیرد @Catch(HttpException) export class HttpExceptionFilter implements ExceptionFilter { catch(exception: HttpException, host: ArgumentsHost) { const ctx = host.switchToHttp(); const response = ctx.getResponse(); const request = ctx.getRequest(); const status = exception.getStatus(); // فرمت خطای یکسان برای کل اپلیکیشن response.status(status).json({ success: false, statusCode: status, path: request.url, message: exception.getResponse(), timestamp: new Date().toISOString() }); } } // ثبت سراسری در main.ts // app.useGlobalFilters(new HttpExceptionFilter()); // یا @Catch() بدون آرگومان برای گرفتن همه نوع خطا (حتی خطاهای غیرمنتظره) @Catch() export class AllExceptionsFilter implements ExceptionFilter { catch(exception: unknown, host: ArgumentsHost) { const status = exception instanceof HttpException ? exception.getStatus() : 500; // خطای ناشناخته = 500 // ... } }

Custom Decorators — ساخت decorator اختصاصی

گاهی می‌خواهید کدی که در چند جا تکرار می‌شود را در یک decorator ساده جمع کنید — مثلاً گرفتن کاربر لاگین‌شده از request:

decorators/current-user.decorator.ts
import { createParamDecorator, ExecutionContext } from '@nestjs/common'; // این decorator کاربر لاگین‌شده را از req.user (که Guard گذاشته) استخراج می‌کند export const CurrentUser = createParamDecorator( (data: unknown, ctx: ExecutionContext) => { const request = ctx.switchToHttp().getRequest(); return request.user; } ); // ❌ بدون custom decorator — تکراری در هر Controller @Get('profile') getProfile(@Request() req) { return req.user; } // ✅ با custom decorator — تمیز و خوانا @Get('profile') getProfile(@CurrentUser() user: User) { return user; } // می‌تواند یک property خاص هم بگیرد export const CurrentUser = createParamDecorator( (data: string, ctx: ExecutionContext) => { const user = ctx.switchToHttp().getRequest().user; return data ? user?.[data] : user; // @CurrentUser('email') فقط ایمیل را برمی‌گرداند } );

Testing در NestJS

NestJS با TestingModule به شما اجازه می‌دهد Dependency Injection را در تست هم استفاده کنید — به‌راحتی می‌توانید dependency واقعی را با mock جایگزین کنید:

users.service.spec.ts
import { Test, TestingModule } from '@nestjs/testing'; import { UsersService } from './users.service'; import { getModelToken } from '@nestjs/mongoose'; describe('UsersService', () => { let service: UsersService; let mockUserModel: any; beforeEach(async () => { mockUserModel = { findById: jest.fn(), create: jest.fn(), }; // TestingModule دقیقاً مثل یک Module واقعی است، ولی dependency را می‌توانید mock کنید const module: TestingModule = await Test.createTestingModule({ providers: [ UsersService, { provide: getModelToken('User'), // جایگزین کردن Mongoose Model واقعی useValue: mockUserModel, }, ], }).compile(); service = module.get<UsersService>(UsersService); }); it('باید کاربر را بر اساس id برگرداند', async () => { mockUserModel.findById.mockResolvedValue({ id: '1', name: 'Ali' }); const result = await service.findOne('1'); expect(result.name).toBe('Ali'); expect(mockUserModel.findById).toHaveBeenCalledWith('1'); }); });

تست E2E با supertest — یادآوری فصل ۵۱

app.e2e-spec.ts
import * as request from 'supertest'; import { Test } from '@nestjs/testing'; import { AppModule } from '../src/app.module'; describe('Users E2E', () => { let app; beforeAll(async () => { const moduleRef = await Test.createTestingModule({ imports: [AppModule], // کل اپلیکیشن واقعی }).compile(); app = moduleRef.createNestApplication(); await app.init(); }); it('GET /users باید لیست کاربران برگرداند', () => { return request(app.getHttpServer()) .get('/users') .expect(200) .expect(res => { expect(Array.isArray(res.body)).toBe(true); }); }); });

NestJS Microservices — یادآوری فصل ۴۴ و ۶۱

NestJS به‌صورت built-in از چند transport برای ارتباط بین سرویس‌ها پشتیبانی می‌کند — TCP، Redis، Kafka، gRPC (فصل ۶۱) و RabbitMQ — بدون نیاز به نوشتن دستی هر بخش:

main.ts — راه‌اندازی Microservice با TCP
import { NestFactory } from '@nestjs/core'; import { Transport } from '@nestjs/microservices'; const app = await NestFactory.createMicroservice(AppModule, { transport: Transport.TCP, options: { host: '0.0.0.0', port: 3001 }, }); await app.listen();
users.controller.ts — دریافت پیام از سرویس دیگر
import { MessagePattern, Payload } from '@nestjs/microservices'; @Controller() export class UsersController { // معادل یک "endpoint" داخلی بین سرویس‌ها — نه HTTP @MessagePattern({ cmd: 'get_user' }) getUser(@Payload() data: { id: string }) { return this.usersService.findOne(data.id); } }
orders.service.ts — صدا زدن سرویس دیگر با ClientProxy
import { ClientProxy, Transport, ClientsModule } from '@nestjs/microservices'; // در module: ثبت اتصال به سرویس Users // ClientsModule.register([{ name: 'USERS_SERVICE', transport: Transport.TCP, options: {...} }]) @Injectable() export class OrdersService { constructor(@Inject('USERS_SERVICE') private usersClient: ClientProxy) {} async createOrder(userId: string, items: any[]) { // send() یک پیام می‌فرستد و منتظر پاسخ می‌ماند (مثل یک تابع remote) const user = await firstValueFrom( this.usersClient.send({ cmd: 'get_user' }, { id: userId }) ); if (!user) throw new Error('کاربر یافت نشد'); // ادامه ساخت سفارش... } }

جدول خلاصه — کدام ابزار برای چه کاری

Guard

تصمیم می‌گیرد آیا اجازه ورود به route را می‌دهد یا نه (authentication/authorization).

Pipe

داده ورودی را validate یا transform می‌کند، قبل از رسیدن به handler.

Interceptor

کد قبل/بعد از handler اجرا می‌کند — logging، caching، تبدیل response.

Exception Filter

فقط وقتی خطا رخ دهد اجرا می‌شود — فرمت پاسخ خطا را کنترل می‌کند.

نکات کلیدی برای مصاحبه

  • ترتیب اجرای NestJS: Middleware → Guard → Interceptor (قبل) → Pipe → Handler → Interceptor (بعد) → Exception Filter.
  • Pipe برای validation و transform ورودی — ParseIntPipe، ValidationPipe از پرکاربردترین‌ها.
  • Interceptor بر پایه RxJS ساخته شده — با next.handle().pipe() می‌توانید قبل و بعد از handler کد اجرا کنید.
  • Exception Filter فرمت خطا را در کل اپلیکیشن یکسان می‌کند — با @Catch() تعریف می‌شود.
  • Custom Decorator با createParamDecorator ساخته می‌شود — کد تکراری را در یک اسم ساده جمع می‌کند.
  • در تست NestJS، TestingModule اجازه می‌دهد به‌جای dependency واقعی، mock تزریق کنید — بدون نیاز به دیتابیس واقعی.
  • سوال رایج: «فرق Guard و Interceptor چیست؟» — Guard فقط تصمیم می‌گیرد اجازه ورود هست یا نه (بله/خیر)؛ Interceptor کد اضافه اجرا می‌کند و حتی می‌تواند response را تغییر دهد، نه فقط رد یا قبول کند.
  • یک تله رایج: قرار دادن منطق validation سنگین داخل Controller به‌جای Pipe یا DTO — این باعث تکرار کد و سخت شدن تست می‌شود؛ Pipe دقیقاً برای همین ساخته شده.
  • سوال رایج: «چطور NestJS بین چند سرویس بدون HTTP ارتباط برقرار می‌کند؟» — با ماژول Microservices و transport هایی مثل TCP، Redis، یا gRPC (فصل ۶۱)؛ @MessagePattern روی سرویس گیرنده، ClientProxy.send() روی سرویس فرستنده.
  • @nestjs/testing امکان تست Unit (با mock) و E2E (با کل اپلیکیشن واقعی از طریق supertest) را در یک اکوسیستم یکپارچه می‌دهد.
  • در مصاحبه NestJS، معمولاً از شما خواسته می‌شود توضیح دهید یک Guard یا Interceptor سفارشی چطور می‌نویسید — آماده باشید یک مثال ساده (مثل چک کردن یک header خاص) را زنده بنویسید.
