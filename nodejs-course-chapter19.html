Docker
کانتینرسازی

Docker به شما اجازه می‌دهد اپلیکیشن و همه وابستگی‌هایش را داخل یک «کانتینر» بسته‌بندی کنید. این کانتینر روی هر سیستمی به یک شکل اجرا می‌شود — مشکل «روی سیستم من کار می‌کند ولی سرور نه» حل می‌شود.

Image Container Dockerfile docker-compose Volumes

Docker چیست؟ چرا لازم است؟

تصور کنید Node.js نسخه ۱۸ روی سیستم شما نصب است ولی سرور نسخه ۱۶ دارد. یا MongoDB نصب نیست. Docker این مشکلات را حل می‌کند: همه چیز (Node، MongoDB، Redis) داخل کانتینر می‌رود و همه جا یکسان اجرا می‌شود.

تشبیه ساده: Docker مثل یک کارتن引 است که همه چیز را داخلش می‌گذارید — کد، Node.js، وابستگی‌ها. هر جا این کارتن را ببرید، محتوایش یکسان است و به همان شکل کار می‌کند.

سه مفهوم اصلی

📦 Container — نمونه اجرایی
🖼️ Image — قالب read-only
📄 Dockerfile — دستورالعمل ساخت Image

Dockerfile دستورالعمل ساخت Image است. از Dockerfile یک Image می‌سازید. از Image می‌توانید چند Container اجرا کنید — مثل class و instance.

Dockerfile برای Node.js

Dockerfile یک فایل متنی است که به Docker می‌گوید image چطور ساخته شود. هر خط یک دستورالعمل است:

Dockerfile
# FROM — از چه image پایه‌ای استفاده کنیم # node:20-alpine — Node 20 روی Alpine Linux (سبک‌تر) FROM node:20-alpine # WORKDIR — پوشه کاری داخل container WORKDIR /app # اول package.json را کپی کنیم (برای cache بهتر) # Docker هر لایه را cache می‌کند — اگر این فایل تغییر نکرد # npm install دوباره اجرا نمی‌شود COPY package*.json ./ # RUN — دستوری که داخل container اجرا می‌شود RUN npm ci --only=production # npm ci سریع‌تر از npm install و package-lock را رعایت می‌کند # بقیه فایل‌ها را کپی کن COPY . . # EXPOSE — پورتی که container استفاده می‌کند (فقط documentation) EXPOSE 3000 # CMD — دستوری که container شروع به کار می‌کند CMD ["node", "src/server.js"]
.dockerignore — این فایل‌ها را کپی نکن
node_modules .git .env *.log dist .DS_Store
terminal — ساخت و اجرای container
# ساخت image از Dockerfile docker build -t my-node-app . # -t اسم image، . یعنی Dockerfile در همین پوشه # اجرای container از image docker run -p 3000:3000 my-node-app # -p 3000:3000 یعنی port 3000 سیستم به port 3000 container # اجرا در background docker run -d --name my-app -p 3000:3000 my-node-app # پاس دادن environment variables docker run -d \ -p 3000:3000 \ -e NODE_ENV=production \ -e DB_URL=mongodb://db:27017/myapp \ my-node-app # مشاهده containerهای در حال اجرا docker ps # لاگ‌های container docker logs my-app -f # ورود به shell داخل container docker exec -it my-app sh # متوقف و حذف container docker stop my-app docker rm my-app

docker-compose — چند سرویس با هم

در پروژه واقعی، علاوه بر Node.js به MongoDB، Redis و شاید چیزهای دیگر هم نیاز دارید. docker-compose به شما اجازه می‌دهد همه سرویس‌ها را در یک فایل تعریف کنید و با یک دستور همه را اجرا کنید:

docker-compose.yml
version: '3.9' services: # سرویس Node.js app: build: . # از Dockerfile در همین پوشه بساز ports: - "3000:3000" environment: - NODE_ENV=development - DB_URL=mongodb://mongo:27017/myapp - REDIS_URL=redis://redis:6379 volumes: - .:/app # پوشه جاری به /app map شود - /app/node_modules # node_modules را override نکن depends_on: - mongo - redis command: npm run dev # سرویس MongoDB mongo: image: mongo:7 # از Docker Hub بگیر ports: - "27017:27017" volumes: - mongo-data:/data/db # داده‌ها persist بمانند environment: - MONGO_INITDB_ROOT_USERNAME=admin - MONGO_INITDB_ROOT_PASSWORD=secret # سرویس Redis redis: image: redis:7-alpine ports: - "6379:6379" volumes: - redis-data:/data # Volume‌ها — داده‌های persistent volumes: mongo-data: redis-data:
terminal — کار با docker-compose
# شروع همه سرویس‌ها docker-compose up docker-compose up -d # در background docker-compose up --build # image را دوباره بساز # متوقف کردن docker-compose down docker-compose down -v # volumes را هم حذف کن # لاگ‌ها docker-compose logs -f app docker-compose logs -f mongo # restart یک سرویس docker-compose restart app # اجرای دستور در container docker-compose exec app sh docker-compose exec mongo mongosh

Multi-stage Build — image سبک‌تر

برای production باید image کوچک‌تر و امن‌تر باشد. با Multi-stage build ابزارهای توسعه را در مرحله build نگه می‌داریم و فقط نتیجه را به image نهایی می‌بریم:

Dockerfile.production
# مرحله ۱ — Build FROM node:20-alpine AS builder WORKDIR /app COPY package*.json ./ RUN npm ci COPY . . RUN npm run build # TypeScript compile # مرحله ۲ — Production (فقط نتیجه build) FROM node:20-alpine AS production WORKDIR /app # فقط production dependencies COPY package*.json ./ RUN npm ci --only=production # فقط فایل‌های build شده (نه source code) COPY --from=builder /app/dist ./dist # user غیر root برای امنیت RUN addgroup -g 1001 -S nodejs && adduser -S nodejs -u 1001 USER nodejs EXPOSE 3000 CMD ["node", "dist/server.js"]

نکات کلیدی برای مصاحبه

  • Image read-only است — مثل قالب. Container instance اجرایی آن است.
  • .dockerignore مثل .gitignore — فایل‌هایی که نباید داخل image بروند را مشخص می‌کند.
  • در Dockerfile اول package.json را کپی کنید، سپس npm install، سپس بقیه کد — برای استفاده از cache.
  • docker-compose برای orchestration چند سرویس — development را ساده می‌کند.
  • Volumes برای داده‌های persistent — بدون volume، داده‌های MongoDB با حذف container از بین می‌رود.
  • در production از multi-stage build استفاده کنید — image کوچک‌تر و امن‌تر.
  • سوال رایج: «چرا لایه‌بندی (layer caching) در Dockerfile مهم است؟» — هر دستور یک لایه جدید می‌سازد؛ اگر ترتیب درست باشد (چیزهای کم‌تغییر اول)، بیلد بعدی از cache استفاده می‌کند و خیلی سریع‌تر تمام می‌شود.
  • یک تله رایج: کپی کردن کل پروژه با COPY . . قبل از npm install — با هر تغییر کوچک کد، کل cache باطل می‌شود و npm install دوباره از صفر اجرا می‌شود.
  • alpine images (مثل node:20-alpine) خیلی کوچک‌تر از نسخه معمولی هستند — برای production توصیه می‌شوند، ولی گاهی با بعضی پکیج‌های native سازگاری کمتری دارند.
  • برای دیدن لاگ container در حال اجرا از docker logs -f container_name استفاده کنید — مثل tail -f روی فایل لاگ.
